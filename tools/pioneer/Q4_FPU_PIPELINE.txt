Compressed Q4 block -> BF16 -> fast FPU:OFFBOARD integration
=========================================================

PioneerQ38Q4FpuBlock.h and blackhole_q38_q4_fpu_block.cpp implement one
COMPLETE32-output,K256 block,all8 Q4 scale groups,all4 matrix fidelity phases.
Two complete jobs execute in the NEW distinct QFP1 image. No installed driver,
native lease,Assistant,cache or Work mode accepts/selects this image.

Data path
---------
PioneerQ38Q4FpuBlockData.h is a DIFFERENT explicit CPU-preparation recipe:
32 original144B row blocks become4096 UNCHANGED packed quant bytes plus2048B
EXACT FP32 coefficients/negative minima. Finite half subnormals and signed
zeros are preserved. All metadata validate before atomic publication;no
BF16 weight expansion,learned products or device IO occurs in preparation.
Do not substitute this for the installed lossless cache layout/recipe.

The6144B GDDR payload proposal is33.3% larger than original4608B Q4 blocks,
but29.4% smaller than8704B native BFP8 for the same8192 weights. These are
DATA sizes,not an allocation,whole-model fit,bandwidth or throughput proof.
No whole-model prepared cache is built or selected by this prototype.

The prototype's separately owned L1 stages have private zero64B headers:
 raw panels90000/stride320,16x256B;metadata94000/stride128,32x64B;
 input96000/stride128,8x64B;immutable zero buffer97000/1024B;results98000.
No descriptor aliases payload/header data. CPU tests map every actual address;
there is no descriptor normalization or decoded shadow-operand injection.

For each32-K group,actual UNPACK-to-Dst instructions load all metadata and
four packed raw faces. A single SFPTRANSP per parity replicates16 exact row
coefficients/negative minima across needed lanes. Both register groups/all
eight registers and all32 lanes are defined. Only the original first subvector
is used after transpose;DEFINED nonzero padding is harmless and tested.
The exact10-instruction decoder produces BF16-RNE operands. FP32 SFPSTORE
and MOVD2A publish all64 source rows before the fast MVMUL consumer. ALL4
fidelity phases,source-bank handoffs and REAL completion waits are retained.
Dst32 dot rows32/40 are physically disjoint from raw Dst16 rows0..63,
decoded Dst32 rows64..127 and metadata Dst32 rows128..143. Padding is fully
initialized BEFORE partial writes. Output is read only after clean completion.

The image performs NO scalar weight/metadata/activation/GDDR/NoC/host reads,
and no scalar operand writes. Data already must be present in owned L1.
Future GDDR streaming/native ownership is NOT implemented by this producer.
