Isolated native BFP matvec diagnostic candidate (NOT INSTALLED)
=============================================================

Purpose
-------
Physically qualify native cached-weight-format math before fullK streaming
and model/cohort integration. This is a real kernel driver/client adapter,
not Work inference. Only two immutable asymmetric synthetic fixtures are
accepted:one BFP4_B or BFP8_B32x32 tile with BF16 activations. No caller code,
weights,pointers,PCI/NoC addresses,routes,clocks or reset commands are accepted.
The candidate is unselected by the running Assistant and stable041 driver.
It has not yet been staged,loaded or executed on the Pioneer.

Build
-----
  python3 tools/pioneer/build_native_bfp_diagnostic.py \
    /Volumes/HaikuBuildLocal/generated.riscv64 /absolute/fresh-output

This compiles BOTH RV32I images from source,requires their exact boot/text
SHA and entry/done/park/fault symbols,then generates immutable code arrays.
It compiles/links the distinct native driver and fixed-fixture Haiku client,
plus the unchanged-feature default43 control. It never stages,installs,
reloads,opens a card or starts a test. Optimized Python is refused so build
assertions cannot silently vanish. Existing private reload guard is reused,
not rebuilt/installed by this builder. All conventional native driver entry
exports are checked,and the compiled legacy find_device is proved NULL-only.

Only an independently prepared/frozen physical trial may install and invoke:
  pioneer-native-bfp-diagnostic --fixed-bfp4
or --fixed-bfp8. No default command/automatic device discovery/start exists.

Owner/lifecycle
---------------
Distinct tag2026110300010078,private pointer-free360-byte protocol. The
conventional driver publishes ONLY root/team-bound metadata plus fixed
SUPPORT/RUN/END;old model/Work/data upload/PCI experiments are not routed.
Reserved tag78 cannot compile as an ordinary legacy driver. Each open cookie
can attempt RUN only once;fixed format,generation,nonce and explicit accept
are bound across END. Foreign owners,cold/quiesced state and extra open FDs
refuse hardware entry. No reset or cold-latch clear is exposed to userspace.

Exact Pioneer PCI layout,quiet MSI/MSI-X/ROM/commands,firmware18.5 telemetry,
seven-bank source translation,all120 enabled cores held,and sole-tile NoC0
identity/routes/idle queues are required before execution. Only host memory
decoding is enabled,not bus mastering. No host DMA or device NoC command is
issued. No ARC busy/clock/voltage control or firmware/boot write is performed.

The heap owner retains PCI reservation,mappings,original TLBs and3548 saved
L1 words:boot4B,code4KiB,private stack8KiB,weight/header1104B,input/header528B,
output256B,status12B. It stages/reads back the complete fixed footprint and
publishes boot last. The sole idle context is explicitly reset;TRISC0 alone
starts. Existing Src/Dst/config/local-RISC state is deliberately disposable,
NOT preserved as though it belonged to an active model. Other cores stay held.

The image performs both source-bank jobs and copies64 actual FP32 result
words. The host requires full phase/count/marker,stable source/TLB/reset and
two allowed frontend PC snapshots;PC alone is NEVER completion. Both guard
PCs are self-loops. Host polling is capped at20000 iterations/2seconds when
MMIO returns. It cannot guarantee bounded completion of a platform bus fault.
The image separately has bounded GPR completion waits and a fault-only park.

RUN returns while the complete image remains PARKED AND OWNED. The separate
userspace diagnostic checks all64 fixed dyadic outputs BIT-EXACT against
independent long-double arithmetic. This is debug synthetic validation,not
CPU learned products in Work. Only an explicit accepted END re-proves terminal
state,holds/reset-initializes that sole context,proves all cores held,restores
and verifies L1 then TLBs,then the outer PCI transaction/reservation is closed.

Timeout,fault marker,wrong PC,source/ownership drift,dropped stage/start/STOP,
restore failure,RUN reply failure,numerical failure or close without END require
quarantine/retention. No watchdog reset,blind restore,second start,automatic
END,unreserve,unmap or heap/cookie deletion is authorized after UNKNOWN.
Outer VM/PCI restoration stops at its FIRST failing step,without retry or
later device writes;remaining resources and snapshots are retained. A failed
reply AFTER a proven clean END does not retroactively make resources live.
The separate KEEP_LOADED guard persists the fault across module reload.
Recovery is external and controlled under the development-box power policy.
Never run a second trial or hot-swap on the assumption that an SSH timeout
means the original parent or its hardware resources have stopped.
