Compressed Q4 -> fast FPU operand prerequisite
============================================

PioneerQ38Q4FpuDecode.h is a NEW OFFBOARD instruction producer. Only the new
Q4 FPU block prototype selects it;no accepted native owner,installed driver,
Assistant or Work mode does. The existing
lossless disk cache and its original quantized bytes remain unchanged.

Why this path
-------------
The qualified native BFP8 experiments expand weights before uploading them.
That has a capacity and batch-one weight-traffic cost (see
NATIVE_BFP8_WEIGHT_CACHE.txt). This candidate instead decodes small original
Q4 groups ON THE CARD into transient BF16 operands for the fast matrix unit.
It does not store an expanded model in GDDR or require CPU learned products.
The decoder is implemented here;the separate K256 source-load/FPU pipeline is
now OFFBOARD-qualified (Q4_FPU_PIPELINE.txt),not physically/native qualified.
No theoretical or measured tokens/sec is implied.

Exact register contract
-----------------------
All32 lanes enabled, fresh ready registers and no conditional predication:
  Prepare:1=finite original half d in FP32,2=half dmin in FP32,
          3=original unsigned6-bit scale,4=original unsigned6-bit minimum.
  Output:1=d*scale,2=-(dmin*minimum),4=15,5=1,6=32767,7=0xffff0000.
  Decode:0=fresh unsigned ORIGINAL packed byte0..255;select low/high nibble.
  Output:0=nearest-even BF16 value represented in FP32,low16 bits zero.
  Decode preserves1,2,4,5,6,7;clobbers0,3;changes no lane flags.

Prepare emits12 instructions/group;each decode emits10/32 values. Constants
are reused ONLY within their original metadata group. d*scale*q contains at
most21 significant bits,so its FP32 product is exact. A single SFPMAD then
performs the subtract without removing an original product rounding point.
The final conversion is EXPLICIT BF16-RNE,not lossless Q4 and not existing
Work math. BF16 operands and full matrix accumulation still require separate
quality qualification. No comparator/reference/tolerance is changed.

The half domain implies finite weights below2^26,nonzero spacing at least
2^-24,so this bounded producer needs no hidden denormal/NaN/overflow path.
SFPSTORE/BF16 truncates;SFPSTOCHRND nearest is ties-away,not nearest-even.
Six integer operations implement nearest-even and preserve signed zero.
