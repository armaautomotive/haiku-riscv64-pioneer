P100A / Qwen 27B: bounded work plan
====================================

Updated November 6, 2026. These checkpoints organize the work; they do not
replace or reduce the overall goal.

Overall goal
-------------

Usable self-hosted Qwen3.8-27B Q4_K_M on P100A, as fast as safely possible,
targeting 20 tokens/second. Work has no CPU model inference/reference or
fallback. CPU validation stays separate. Preserve Haiku boot, 64 CPUs,
full RAM and working Assistant. Push tested checkpoints.
20 tokens/second is UNMET and UNPROVEN.

Best saved model rate: about 0.173 tokens/second (92).
Most recent model rate: about 0.082 tokens/second (110).
P100A_CURRENT_STATUS.txt is the authoritative plain-language summary.

3. Decide the performance route -- NOT STARTED
----------------------------------------------

Use isolated timings, existing model profiles and weight-traffic budget
to identify costs actually removed and costs remaining.
Record a conditional achievable range, assumptions and uncertainty,
not a guaranteed whole-model speed.
Decision: integrate a demonstrated useful candidate, or reject/change the
algorithm. A small gain does not show 20 tokens/second is close.
This decision does not finish the overall objective.

4. Integrate and measure the complete model -- NOT STARTED
-----------------------------------------------------------

Use the accepted path in full-card Work, including remaining formats,
attention and state. Complete real requests and assess more than the
existing counting answer. Run the matched public throughput workload and
compare with faster saved tag 92.
Report quality, loading, prompt processing and generation separately.
Require actual process exits, independent restoration/platform checks
and a pushed checkpoint. A completed request is not usable speed.

5. Make the accepted engine usable -- NOT STARTED
--------------------------------------------------

Keep weights loaded between requests with explicit load/unload lifetime,
avoid repeated preparation where safe, then expose the proven mode in
Assistant. Verify repeated warm requests and actual UI behavior.
Do not replace working Assistant with an unqualified slower experiment.

Reporting rules
----------------

Only one implementation checkpoint is current. Close each with:
  Changed code / local tests / hardware tests / answer quality /
  measured speed / decision / next checkpoint.

Say "not tested" where appropriate. Test counts, commits, instruction-model
passes and microbenchmarks are not model throughput or percentage complete.
Do not reopen closed trials or create parallel work streams without a
concrete dependency on the current checkpoint.
Do not promise a completion date or 20 tokens/second without evidence.
