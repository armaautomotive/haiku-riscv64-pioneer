Matrix-FPU status clarification, November 16, 2026
------------------------------------------------
The accepted fastest vector92 model path already uses the Tensix matrix FPU
for its Q4 dot products: its unchanged worker issues four MVMUL fidelity
phases per panel, while SFPU instructions do Q4 metadata/unpack/vector work.
The November 6 profile build explicitly retained all ten vector92 worker
arrays; the root-only timing addition did not replace worker arithmetic. The
offline matrix-phase test exhaustively checks the emitted four-phase schedule
for all 65,536 signed-byte pairs. Therefore the 0.1728 tok/s baseline is not
a CPU matrix-multiply baseline that can be sped up simply by moving MVMUL to
the FPU; it already does that. Remaining leverage is in the rest of the
on-card projection pipeline, parallel scheduling/data movement, recurrent
state/attention, or a demonstrably better FPU-worker design.

A separate Q4 FPU streaming prototype also passed a bounded November 4
physical diagnostic: 576/576 exact output words across nine full-K samples,
with complete journal/lifecycle restoration and stable-driver recovery. That
was one compute tile, 32 output rows per sample, and diagnostic BF16 input
vectors instead of prompt activations. It proved another numerical primitive
and stream protocol on-card, not better full-model inference, model quality,
full-card utilization, or tokens/sec. See
benchmarks/qwen38-native-q4-fpu-stream-physical-20261104.txt and
benchmarks/qwen38-fast-decode-profile-root-20261106.txt.

A host-only operation inventory compared the emitted arithmetic templates
per 32-row x K256 tile. The vector92 Q4 path counts 846 Op calls (metadata335
+ affine-Dst24 + 128 four-phase MVMUL operations); the separate cached-FPU
stream template counts 4,664 Op calls with the same 128 MVMUL operations.
This is a 5.51x instruction-issue-count difference in the prototype's support
work, not a cycle or speed measurement; it argues against promoting that
prototype without a matched hardware timing comparison. Reproduction source:
tools/pioneer/pioneer_q38_vector_q4_issue_inventory.cpp; cached-FPU counts are
recorded in benchmarks/qwen38-performance-budget-20261106.txt. No physical
test was run for this inventory.

A newer mixed-format native87 FPU stream client/typed-parent passed its
offboard SDK, role-refusal, original-weight identity, and independent exact
reference tests for 17 samples (1,088 expected words); this remains software
qualification only. Its old one-shot hardware script is tied to stable-driver
generation 10 and its prior stage is spent. Live state on November 16 is
stable041 generation 2, idle, with 64 CPUs and full memory. Do not reuse that
script/stage. The next physical gate is a newly built and independently
qualified one-shot candidate bound to the current generation and exact source
identities. Even after that, FPU arithmetic must be integrated with real
prompt activations, all required model projections/state, checked full-model
quality, and matched generation timing before it can be called a performance
improvement. The last qualified full-Q4 rate remains about 0.1728 tok/s; no
new speed result exists and the 20 tok/s target remains unmet.
