P100A / Qwen 27B -- current status
================================
Updated November 6, 2026. These are saved results, not live telemetry.
Target: usable self-hosted 27B, aiming for 20 tokens/second. NOT ACHIEVED.

What works
----------
Complete 27B requests have run on the actual P100A without CPU model math.
The CPU still manages files, tokenization, launching and observing the work.
Tests produced "Hello! How can" and a 32-token counting answer.
Those short tests do not establish general answer quality.

---------------

The latest path is slower and has NOT replaced Assistant's backend.
No newer full-model speed result exists. Model loading time and first-token
latency also still need separate measurements.

Current bounded task
--------------------
Make the GPU's Q4 weight-processing kernel faster, then measure it on-card.

Completed offline: an issue-overhead optimization that processes adjacent
chunks together. It preserves the arithmetic, GPU instruction order,
formats, completion checks, transfers and existing memory limits.
It passed output checks using original model weights: 576 exact results.
Independent working-tree and clean-source test runs passed.
The compiled-program test executes 5.1-5.3% fewer RV32 instructions.
That is NOT a measured improvement in card time or model tokens/second.
No installed driver or Assistant backend was changed.

Next: test this candidate through a fresh diagnostic build and measure
the same two operations against the completed on-card baseline.
Never replay the old, already-used 107-a hardware trial.
If faster, integrate it and repeat the same complete 27B benchmark.
Only a measured full-model improvement justifies promotion to Assistant.
This small change leaves the GPU math-operation count unchanged; reaching
the overall target will require larger kernel/dataflow improvements too.
