P100A / Qwen 27B: current status
================================
Updated November 6, 2026. Model: Qwen3.8-27B Q4_K_M.

The target is fast self-hosted inference, ideally 20 tokens/sec. It has NOT
been delivered, and 20 tokens/sec is unproven. A short 27B request runs all
model inference on the P100A, including attention and state; the CPU handles
files, preparation, vocabulary/text and lifecycle, not inference or fallback.

Latest real result
------------------
* Generation: 0.17290 tokens/sec, about 5.8 seconds per committed position.
* The unchanged fast run was 0.17281; these single runs do NOT prove a speedup.
* The answer counted from 1 through 14 before the 32-token output cap. This
  is one short response, not broad correctness or production qualification.
* Answer-ready took 35.11 minutes after Generate; this excludes prior source
  authentication. Weights were released at END. Warm Assistant is unfinished.

Measured generation bottlenecks
-------------------------------
The valid on-card profile attributes 48.85% of generation-body cycles to the
four projection-call phases, 33.67% to remaining recurrent+dense paths, and
11.87% to the output-head matrix. These are controller cycle shares, not
pure FPU/bandwidth measurements. Removing all projection time for free would
still yield only about 1.95x in that scoped breakdown, if everything else
stayed unchanged. No supported 116x route is established.

Four compact goals
-------------------
1. Identify the fastest engine's bottleneck: COMPLETE for one request.
2. Remove one measured overhead: TESTED/REJECTED as a meaningful gain.
   Descriptor reuse ran the complete 27B request but measured essentially
   the same speed. A native BFP4 matrix prototype passed a full-width K5120
   synthetic test on the P100A, measuring 24779/24803 card cycles for a
   preloaded 32-row band. This does NOT include GDDR loading and has NOT
   been integrated into the model or shown to improve model speed.
   Three real-weight bands pass the offline GDDR/compute observer. Their
   synthetic-input output errors are 8.6%–15.8%, so model quality remains
   an important open question before using the approximate format.
   The real-weight BFP4 diagnostic now runs on the card with GDDR loading:
   three K5120 bands returned all 192 expected BFP4 words, with each 32-row
   job taking 227142-227285 card cycles. This is NOT an equivalent-Q4 or
   full-model speed result: the conversion is lossy, and the BFP4 path is
   not integrated. See the physical report for scope and quality limits.
   A CPU comparison using the first prompt token's reconstructed layer-0 FFN input
   measured 5.7%-7.2% relative output error across those three bands versus
   the independent Q4 reference. This is not a full-model quality score.
   A CPU-only comparison of the complete first FFN block now shows 1.81%
   relative L2 error in the layer output for one prompt token. This is not
   a full-model quality result, a card measurement or a speed improvement.
   A separate FFN converter matches all 192 real tensor layouts without
   increasing their byte footprint and matches three card-tested bands.
   A real 7.2 MB fragment also passed a cold disk-cache conversion and a
   warm cache hit with zero source-row reads. This is not yet used by Work.
   A distinct 32-row BFP4 worker leaf now compiles and passes simulated
   RISC-V tests with inputs from ROOT L1 and converted weights from GDDR.
   It is NOT installed or integrated into full-model inference.
3. Measure an accepted improvement on the complete 27B model: NOT ACHIEVED.
4. Keep the model loaded and deliver it through Assistant: NOT STARTED.
