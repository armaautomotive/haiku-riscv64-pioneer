P100A / Qwen27B -- read this first
================================
Updated 2026-11-06 05:03 UTC. Saved evidence, NOT live board telemetry.
Overall goal unchanged: usable self-hosted 27B, targeting 20 tokens/sec.
That goal is NOT achieved. Small milestones below do not redefine success.

What works
----------
The complete 27B model has executed on the actual P100A without CPU model
inference. The last completed experiment returned four expected tokens:
"Hello! How can". This proves one complete request, not broad correctness.
The experiment ended cleanly and restored the normal driver. Its separate
postflight verified 64 CPUs, 137034936320 bytes RAM and unchanged Assistant
and runtime files. There were no live hardware jobs at that checkpoint.

What does NOT work yet
---------------------
Usable speed is not delivered. The last measured older path achieved about
0.16436 tokens/sec after the prompt (about six seconds per output token).
The newer BF16 path has no comparable warm-generation rate yet. Its short
prompt-plus-four-output test took 216.622 seconds versus 175.251 previously:
about 24% LONGER, not a speedup. Neither interval is warm tokens/sec.
The slower experimental candidate has NOT replaced Assistant's backend.

Clean build command (from project root)
---------------------------------------
python3 tools/pioneer/reproduce_qwen27_p100a_checkpoint.py \
  --sdk /Volumes/HaikuBuildLocal/generated.riscv64 \
  --libraries /private/tmp/pioneer-lossless-live-20261103.ulZKfMoS/libraries \
  --out /private/tmp/pioneer-qwen27-checkpoint-NEW

Output must be a NEW absolute directory with an existing canonical parent.
Requires the existing Haiku SDK, four pinned runtime libraries and local
llama Git objects. The command reads only the fixed llama header commit,
not dirty submodule sources. It exports source commit:
17d8162774564f8b57746880b72e273a6040f1b0
The embedded firmware is reused exactly, not newly regenerated by this
command. A hash mismatch fails; it is not accepted as an equivalent build.

Important: this is NOT a hardware-run command. Its exact historical smoke
binary points to spent stage 105-a. NEVER execute that old stage again or
substitute new binaries into its admission. The next benchmark needs fresh
paths, identities and admission checks. No one-command fresh run exists yet.
