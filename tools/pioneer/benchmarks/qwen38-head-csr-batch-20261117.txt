Qwen 27B output-head NoC wait reduction candidate
=================================================

The existing RAW full-card ROOT dispatches 973 vocabulary jobs in nine
waves and each worker returns one local maximum. Up to 119 workers run in
parallel. The host neither computes those logits nor selects the winner.
The final ROOT reduction compares only the 973 local winners. A prior
complete physical vector92 profile measured 11.87% of generation-body
cycles in the entire head-matrix bucket, including on-card coordination.

The current Closed() path performs at least 30 serial NoC operations:
three in Wait, one boot read, 16 source-register reads, one job read, one
doorbell read, and eight counter reads. There are 1,211 such audits per
token: 119 before, 973 in Gather, and 119 after. Add two operations per job
for dispatch/release and four for Gather's separate Wait/partial read, for
at least 42,168 serial operations. This is a source count, excluding loops,
normalization, state, and STOP; not a physical packet or timing capture.

Tenstorrent Blackhole NoC MemoryMap.md specifies only 4 bytes per read
when either address is MMIO. The inspection component queues the existing
source/counter reads as three groups of eight individual 4-byte requests.
It keeps every compared register, uses a distinct low-bit-aligned L1 slot
per reply, and checks FIFO capacity, overflow, drain, transaction counts,
live source callbacks, last-command identity and every returned word.
No tracked frontier advances after a refused or uncertain batch. If this
can replace all 24 register wait points in each Closed audit with three
drains, it removes up to 25,431 serial wait points per token in that path,
not NoC packets or PCIe round trips. No relation to tokens/sec is assumed.

ASan/UBSan tests cover the exact register list, command words and response
slots across 357 worker/group combinations, counter wrap, blocked queue,
lost or corrupt response, command readback and authority faults. Eleven
role refusals covered the original isolated inspection build. The prior
projection counter-gather result is a different experiment and is not
evidence for a speedup in this head.

Linked RAW ROOT inspection build
-------------------------------
The opt-in firmware compiles the batch into the real Closed() path only
when the owner is in phase 4 (head evaluation) and not checking a STOP.
Register groups occupy the same order around boot, job, and doorbell
reads. HeadSeal/Scope keep the genuine device-source, token, owner and head
checks while these narrowly bounded reads are in flight. The batch proves
FIFO enable, completion and exact counts separately. All other paths,
including STOP/cancel, keep the serial checks. The final boot and terminal
instruction words are unchanged, as are the linked recurrent and dense
objects. The existing native participant initializer is capable of sealing
FIFO mode; the new helper only checks it and does not change that mode.

The historical RAW control would not reproduce against current unrelated
package changes. The builder reads the exact archived df48ea751a source,
overlays only these coordinator files and their role headers, recompiles
the unchanged coordinator object, and requires both it and the whole
original linked control ELF to match before linking the candidate. Moving
one small wrapper and compiling the affected guards for size kept the new
code within the fixed regions: text 130,972 of 131,072 bytes; conv 32,320 of
32,768 bytes. A candidate build refused four native/CPU/Work/other-head
role mixes. A second build reproduced the candidate ELF byte-for-byte.
The emitted Closed code calls the new batch wrapper; its
largest individual batch frame is 160 bytes, not a combined stack proof.

One-shot hardware runner preparation
------------------------------------
`build_qwen38_head_csr_trial.py` binds one packaged variant and one exact
observed generation of stable041 to a fresh script. It SHA-checks the
restore template before changing the binding. The script's read-only
preflight checks the idle generation, driver/runtime/guard hashes, exact
variant inputs, model identity, original CPU/RAM counts and that the
stage is on the installation volume. The full same-open model hash and
851 layout checks still run in the worker before execution.

Both variants share an exclusive lock while a trial is active. A cold,
owned or otherwise uncertain exchange preserves the lock and refuses
further exchanges. A spent directory cannot be reused. With an idle
candidate and a valid backup the parent restores stable041 even if the
client fails, but the failure still fails the trial. A successful client
must have 32 output tokens, an available rate, clean exit and empty
stderr; independent full-log and machine postflight checks are still
required before using the data. The runner does not reboot, reset, retry,
remove the installed Assistant, or modify the model.

The generated serial and candidate runners passed syntax checks and 33
fake-manager cases, including stale generations, competing locks, raw
stderr, missing rate, ambiguous exchange, ownership and spent stages.
No runner was staged or executed on the Pioneer in this checkpoint.

---------------------------------------------------------

profile on both the raw and the native-Q8 wire ROOT. The builder
authenticates the complete original for each arm, copies only the
measured head/owner-scope changes from their pinned source, and
