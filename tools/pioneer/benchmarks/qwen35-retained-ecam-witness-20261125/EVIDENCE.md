# Retained SG2042 controller lease witness

The current synchronous recovery gateway releases its controller lease when a callback returns, even if a reset remains pending. An earlier negative control reproduced access by another simulated thread in that interval. This isolated, non-loadable controller witness adds a retained lease state: a kernel-owned identity and session begin a lease, the owning thread can park it, and the same identity, session and ticket can resume on a later thread without admitting intervening controller-mediated config access. While parked, waiters are awakened and config reads/writes fail closed with `B_DEV_NOT_READY`. Generic lease release cannot release a retained lease; release requires the owning thread, matching identity/session/ticket, the pinned controller attributes and a caller-supplied authorization flag.

ASan/UBSan tests exercised the actual extracted controller methods and config read/write methods with fake locks and fake MMIO: blocking while owned, wake-and-fail on park, config read/write refusal without touching the fake root, stale tickets, wrong identity/session, root mismatch, resume on another thread, two competing resumptions, unauthorized finish and valid release. The prior qualification-controller and ordinary lease tests also passed. The actual ECAM controller source compiled for Haiku/RISC-V under the isolated witness flags; its `InitDriver` disassembly returns `B_NOT_ALLOWED`. Preprocessor checks reject the retained flag without the recovery witness and reject combinations with qualification or the existing general gateway. The pinned fixed-probe qualification builder was updated for the changed source hashes; it reproduced both the saved baseline and the previous qualification binary `190980822c2587dc013326e1ae144851f26a2ecc70b303c4eb392ebd15c6f3a2` byte for byte. No image was installed or booted. The broad recovery regression exited 0 (`/private/tmp/q35-retained-ecam-regression-20261125.log`); it started before the final direct config-read/write and concurrent-resume test additions, which were then compiled and passed separately with ASan/UBSan.

The release flag is only a **caller assertion**, not proof that reset, PCIe, mappings, DMA, firmware or the fleet is safe. The identity pointer and session need independently pinned lifetime, unforgeable ownership and unique generation; thread exit and thread-ID reuse need handling. Controller/device removal, profile checks before lease acquisition, lock ordering, firmware, BAR/MMIO, DMA and clients outside this controller remain unresolved. No module API exports these methods, the recovery gateway does not invoke them, and the witness cannot initialize as a host controller. No hardware access, in-place recovery, model output or throughput is established. Do not enable it on the Pioneer without completing those lifetime and recovery proofs.
