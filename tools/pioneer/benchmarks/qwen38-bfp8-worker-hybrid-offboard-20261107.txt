BFP8 returning worker and relocated hybrid jobs: OFFBOARD, 2026-11-07
====================================================================

Purpose: connect the possible mixed BFP4/BFP8 layout to actual per-worker
jobs, and implement the higher-precision returning arithmetic leaf. The
existing Q4 Work engine and Assistant are unchanged. This checkpoint does
NOT execute the new worker on the card or measure tokens/sec.

New BFP8 worker data has a distinct job magic and C64 staging geometry:
1088-byte weight tiles from card GDDR, BF16 activations from ROOT L1, and
four FPU fidelity phases. Each 32-row band returns into its worker output
area. The FPU instruction/config stream for K5120 and K17408 matches the
previous C64 BFP8 diagnostic stream exactly. An outer guard currently proves
only that the job frame stays unchanged; it does NOT prove producer lifetime,
converted pages, device ownership or a valid native terminal state.

Tests actually completed:
* Job geometry: 7616 packets spanning all119 peers, both widths and eight
  possible bands, bounds/malformed fields and BFP4-vs-BFP8 magic separation.
* Simulated loader: 238 all-peer/width cases, 37 fault/refusal cases,
  guarded GDDR/ROOT-L1 reads and exact NoC counters. Errors stop without
  retry or later IO.
* The actually linked RV32 worker image produced 64 expected synthetic
  output words for peers1/63/119 at both widths, with frame mutation,
  malformed-frame and dropped-FPU-ack controls. Maximum observed stack was
  624 bytes. It is an instruction simulation, not physical execution.
* The same RV32 image reproduced 64 expected output words for each of three
  pinned, private real-weight BFP8 samples previously used by the separate
  physical C64 diagnostic. Only sample identifiers, not learned data, were
  printed. Private files were hash/mode checked before and after.
* Hybrid job binding covers all 22848 projection jobs / 79872 bands:
  18207 BFP4 jobs and 4641 BFP8 jobs for layers48..60. Relocated addresses,
  bank/row boundaries, format separation, frame mutations and foreign/stale
  plans are checked. The plan is not authenticated weight or device authority.
* The complete previous BFP4 worker suite passed again, including its three
  private real samples. Its linked text SHA remains
  04d43a4e5ad5b766fea07d0d3f9f48168557abda4772826d804f643db644faaf.
