Approximate RMS candidate: synthetic screening only
===================================================
November 7, 2026. The existing recurrent ROOT invokes a 5120-element RMS
whose positive sum emulates binary64 on one scalar controller. A separate
experimental function instead reduces rounded FP32 squares into 16 FP32
accumulators. This changes arithmetic; the old precise implementation is
unchanged. Neither CPU reference inference nor model validation is part of
the candidate function.

On this Mac, a host-only comparison over 256 synthetic rows reported
968144 differing words, worst row relative L2 2.6101209e-7 and worst absolute
error 4.76837158e-7, relative to the existing precise function. Invalid
inputs and output aliasing were refused. This is NOT a real model or quality
evaluation.

Both algorithms were also separately compiled into the existing isolated RV32
RMS test transport. Over six matched synthetic rows, the simulator executed
3105100 precise versus 1479737 candidate instructions (2.0984x ratio), with
9795 differing words and worst row relative L2 1.15798038e-7. Thirteen
invalid-input cases refused without publishing output. This is an instruction
count, NOT P100A cycles, elapsed time, whole-token speed or proof that RMS is
the dominant measured bottleneck. Simulated hardware endpoints and synthetic
inputs do not establish full-model quality.
