Change and scope
----------------
The old opaque worker Stats.minStack records the lowest stack address
accessed, not the lowest reserved SP. A separate read-only observer now
checks the actual SP after each retired ROOT/peer instruction, accumulates
its minimum and counts all instructions. It permits initial boot-zero SP,
then requires aligned SP within [0x6e000,0x70000]; failures are sticky.
It never sets guest registers, memory, PC, products, receipts or readiness.
There is no history reset or watchdog-rebase setter in this observer.

The existing 64-byte Stats layout remains unchanged. A separate 16-byte
Stack result reports reserved/accessed minima and the full retirement count.
Counts must agree with the existing extended instruction-accounting history.
Actual first-matrix, first-layer and whole-flow TEST checkpoints now report
ROOT/119-peer accelerator stack observations separately from HOST kernel
stack qualification. Earlier running binaries do NOT acquire this observer
retroactively, and their results cannot qualify the new observation path.

The helper requires explicit TEST roles. Device images and Work imports,
including defined-zero selectors, are refused. The old TT_WORK_MODE tuning
flag is accepted only inside the exact isolated HOST peer TEST bridge,
never as native/Work permission. The actual native driver rejects the
observer selector even when zero. No firmware bytes, program pins, public
ABI, launch permission, Assistant option or production inference path change.
