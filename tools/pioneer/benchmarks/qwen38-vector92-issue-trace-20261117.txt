Actual linked vector92 worker: submitted work, not silicon time
==============================================================

The existing hardware generation profile assigns 48.85% of controller
cycles to projection calls (including prepare, dispatch, wait, and
finish). It does not identify what the Tensix worker does during those
calls. This independent offline trace executes the exact vector92 worker
used by the fast full-card path and the running tag213 profiler. It does
not generate a new firmware image, install anything, touch the card or
measure tokens/sec.

The runner uses the frozen v4 source revision and all eleven complete
worker ROM pins. Target ELF SHA-256:
  4b3dc0c96d3888b9c43af683f58678cc91cade7c67e955413bad8c5e16d52870

It derives q38_compute_once from the authenticated ELF, records only its
actual dynamic extent and does not alter retired instructions, register
state, results or checks. Top-level Tensix submissions are counted once;
synthetic retirement and replay expansions are not extra submissions.
Config/NoC/ACK load/store callbacks are separate counts. The real worker
consumes synthetic packed weights and inputs using the existing strict
arithmetic and transport model. Both changed-input jobs still have to
produce the expected rows and prove their receipts. The reused worker
must execute its real STOP after the second job.

ASan/UBSan: 18 shapes, 36 full retained jobs; Q8_0, Q4_K and Q6_K;
K=5120/6144/17408 and one or three 16-row groups. Examples, first job:

Matrix counts span 2.087% to 4.582% of top-level submitted commands in
these fixtures. The Q4 worker uses two nonzero fidelity phases, unlike

metadata helper, or compare the resulting total to a different 32-row
cached-FPU kernel. The old template-only comparison is withdrawn; the
partial tool now reports standalone schedules without a synthetic total.

None of these counts is a device-cycle estimate, idle fraction or proof
that a given operation dominates elapsed time. A flood of short config,
decode, affine or synchronization work is a different problem from a
shortage of matrix units. Do not cut commands solely because they are
numerous. The next structural option is to use the native unpack format
for Q8 rather than repeatedly decoding original two's-complement panels
in SFPU: Q8 covers 288 matrices and about 7.58 GB of the ideal per-token
weight traffic (see the exact-model budget). The older native SM7
diagnostic proves numerical handling of its bounded domain, not that the
raw full-model engine can use it or that it is faster. A separate runtime
role must still preserve the original path for incompatible inputs and
must pass exact arithmetic and ownership gates before a hardware test.

Twin-buffer native unpack helper (offboard)
-------------------------------------------
The original direct native unpack helper assumed a single raw tile at
0x90000. The fast vector92 worker alternates two disjoint four-tile
batches. The new helper accepts exactly those eight Q8 tile origins and
only the two 256-byte operand panels. It changes only source interpretation
and the address of the existing native unpack instruction; no new byte
layout, NoC command, worker release or packed-output ownership is granted.
The host-side command model sees one native unpack, one bounded base write,
and two drains per panel. It tests 16 panels bit-for-bit against the
original format's operand builder, both buffers, metadata/padding identity,
exact setup/restore state, 29 inert cases, all byte origins in the allocation,
and a late -128 refusal before publishing converted data. ASan/UBSan passed;
the Work selector was rejected at compile time. No card time was measured.
