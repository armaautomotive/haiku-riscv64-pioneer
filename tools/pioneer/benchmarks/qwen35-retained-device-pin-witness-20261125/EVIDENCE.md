# Retained device-manager driver pin witness

The existing synchronous device-manager pin ends at callback return and therefore cannot preserve a controller driver reference across a parked reset. The new isolated, unexported compile witness uses the actual `device_node::InitDriver` and `UninitDriver` reference counting to retain an initialized node and its ancestors over multiple calls. Its manager-lock-protected monotonic generation, owner and session checks reject stale or mismatched calls. It does not hold the manager lock during a callback, refuses concurrent callbacks or release while one runs, and permanently invalidates the retained pin if it observes removal or an unusable node. Authorized release drops the reference; the authorization is a caller assertion, not a recovery proof.

ASan/UBSan tests ran the actual extracted retained-pin and device-manager lifetime methods against simulated nodes. They checked ancestor references, unlocked callbacks, active-call exclusion, stale identities and tickets, concurrent removal, retained software lifetime, sticky invalidation, explicit release, unique generations across pin objects and generation exhaustion. Existing synchronous pin tests and build-guard checks also passed. The actual device-manager source compiled for Haiku/RISC-V with the original warnings-as-errors flags. A separate temporary target wrapper forced the retained methods to be emitted; its include-only `subobject-linkage` warning was explicitly downgraded. Neither object was linked into a kernel or installed.

The existing experimental pin-kernel builder was updated to verify the exact witness block before comparing the remaining source to the saved mirror. It rejected modified witness and outside-witness source in negative checks, and reproduced the saved ordinary and spin-idle control kernels byte for byte. Its ordinary pin candidate was newly built with SHA-256 `e86e3feb7b8183aa00ba9eced549f41a9461b09ad4fa577990236adadccf6e42`; this differs from the previously recorded candidate, does not enable the retained witness, and was not installed or booted. The broader recovery regression exited 0 (`/private/tmp/q35-retained-dm-reload-final-20261125.log`); the final multi-pin generation assertion was additionally run in the focused pin suite.

This does not prevent device removal, firmware, DMA, MMIO or topology changes during a callback. A postcheck cannot undo access made concurrently with removal. The lifetime of the pin object and owner, thread exit and ID reuse, the controller lease's retained ticket, lock ordering, pre-lease profile access, and a real release proof still need to be tied together. No module exports this retained pin, no recovery path calls it, and no hardware recovery, inference, output or throughput was demonstrated.
