# Two consecutive prompt commands on one simulated fleet

One exploratory `ttsim` process started the compiled sharded resident service and role images once on 120 simulated workers. It sent a 521-step prompt command at position 0, waited for a version-2 root candidate, and checked stable worker mailboxes and sender receipts on all 120 workers. After independent first-layer reference checks, the simulated host acknowledged that candidate and sent a fresh 521-step prompt command at position 1 without restarting or reloading the fleet or state. The second candidate, worker mailboxes, sender receipts and layer outputs passed the same checks. The first command used trigger 1, epoch 22 and step sequences 1–521; the second used trigger 2, epoch 23 and sequences 522–1042. Dynamic patching swapped the history and recurrent-state buffers.

Each ticket contains the 21 authenticated first-layer/model and diagnostic-checkpoint steps used by the preceding fixture, followed by **500 synthetic residual-copy steps**, not the rest of Qwen3.5. The second position checked all 524,288 recurrent-state values and 4,096 gated outputs (maximum absolute errors `3.30248383e-7` and `2.20862447e-7`), 24,576 history entries, and 2,560 final layer outputs (maximum normalized error `9.4990531e-8`). See `run.log`. The word `audited` in that log means the simulator test's mailbox and sender-receipt checks; it did not perform the full physical route, role, queue, firmware or external-writer audit. The process ended after the second candidate without an explicit fleet shutdown sequence.

The complete fixture uses stream leases spaced 2 MiB apart starting at `0x40000000`; the earlier 22-record fixture's 1 MiB spacing was only suitable for its short accessed record range, not 521 records. The diagnostic-copy destination is `0x36000000`, beyond the fixture's FFN weights and below the stream region. The generator rejected an existing output and a corrupted source record in negative tests.

The optimized and ASan/UBSan fixture generators produced identical SHA-256 values for the complete template image `c05d46c9feb36dc57f35589689471a9810a209b484ba99528abef579e5cce3ba` and records `5486a1c893aa7fd2f6cb768fcf95d96e0346c20bac66d7d1535029de8849ef83`. The first and second compact commands had SHA-256 `6d783a778c130e53820f88b6d07c67f3639a738943e84ade258e582429f11907` and `5da1c17ef923c43a6c61b91ba417ea8237a993c6187c0eed902dba3757158511`. The model inputs, simulated images and exploratory simulator are the same as in `../qwen35-state-handoff-sim-20261125/EVIDENCE.md`. The final script differs from the run only in clearer output labels, and its separate helper tests passed. The observed simulator clock rate is **not** a hardware throughput measurement.

This demonstrates a consecutive-command path on one simulated resident fleet, not a complete model, real hardware inference, no-reboot recovery, a clean hardware unload, two valid warm model outputs or 100 decode tokens/sec. The physical PCI recovery lease continuity problem remains unresolved. No card access was performed.

After the two-command run, the refactored harness also reran the original 22-record position-zero fixture successfully: its 21 barriers and independent layer references passed, and record 22 intentionally faulted (`legacy-regression.log`). The simulator state framing and malformed command/receipt tests passed separately.
