Qwen3.8 redistributed/scattered GDN L1-map integration gate — 2026-11-14

What is now connected
--------------------
The exact emitted redistributed+scattered QRJ1 worker was built with the
page-table addresses returned by `PioneerQ38GdnL1PageAllocator`, rather than
only the simulator's convenient fixed test pages. The worker accepted those
addresses, exercised cold fill and warm reuse for resident routes, and used
its existing GDDR current-state transfer for allocator spill routes. The
allocator's lower bound matches the worker's `0x90000` address check.

Validation
----------
Reproduce with:

  `sh tools/pioneer/tests/run_pioneer_q38_gdn_recurrent_redistributed_scattered_image_tests.sh /Volumes/HaikuBuildLocal/generated.riscv64`

The ASan/UBSan emitted-worker test passed 161 exact-output positive executions:
126 resident-map executions and 35 GDDR-spill-map executions. It checked all
8,256 state/output words per execution, 16-step non-resetting state chains,
both GDDR slots, and the explicit spill path. It also passed 4,175 injected
fault cases with no subsequent NoC/SFPU/publication after the fault. The
scatter role gate passed. The legacy non-scattered redistributed worker also
still passes its separate gate (160 positives, 4,170 injected faults).

Capacity evidence remains static: on the alternate 119-peer route, the map
fits at most 2,975 of 4,608 half-states in safe L1 pages; 1,633 spill to GDDR.
The 126/35 figure above is only the number of executions exercised by this
test, not total-model residency.

The allocator test asserts traffic bounds for one complete recurrent-state
sweep. Ordinary warm write-through can avoid 5,950 GDDR read packets /
97,484,800 bytes (92.95 MiB). The L1-authoritative experiment below can also
avoid the same number of GDDR write packets, for a theoretical total of 11,900
avoided transactions / 194,969,600 bytes (185.90 MiB) per sweep. These are
on-card GDDR traffic counts derived from the worker's 16-KiB packet sizes, not
elapsed time or a tokens/sec estimate; write avoidance gives up per-token GDDR
rollback for resident states and requires whole-session discard on fault.

What is still missing
---------------------
The native prepared-Q4 dispatcher does not yet allocate/pin these pages,
populate the worker-local page table, redistribute layer tasks across 119
peers, perform cache warm/cold epoch management, or atomically couple cache
validity to the whole-token GDDR slot commit. Therefore this passing simulator
gate does not make the candidate usable by Assistant/Work and does not prove
that keeping GDN state in L1 improves full-model throughput. The native Qwen
path, other Qwen operations, full-model numerical/lifecycle tests, and a real
Pioneer benchmark remain required. Physical testing is still gated on
out-of-band verification of the Pioneer SSH host key.

2026-11-15 serialized-startup continuation
------------------------------------------
The missing package/startup-data seam is now implemented and pushed in
`1aa55399be` and `cce74ecef3`:

* `PioneerQ38RedistributedGdnPlan` accepts an optional copied 119x9 worker map
  and serializes its eight page addresses plus cold/warm/spill mode into the
  existing redistributed state descriptor. Default descriptors remain
  unchanged; the extension is accepted only under the isolated scattered
  experiment role.
* With that role enabled and redistributed startup explicitly requested,
  `PioneerQ38TokenStartupPlan` builds the deterministic map and passes it into
  each recurrent-layer package. Dense layers keep their legacy packages. The
  allocator metadata is retained on the heap, its lifetime is checked, and
  output aliases into it are rejected.
* `PioneerQ38TokenMetadata::GdnRedistributed` now receives both the requested
  position and the package's committed-token frontier, and rejects the
  transform unless they match. It emits cold mode at position zero, warm mode
  only for later committed resident positions, and keeps spill routes in GDDR
  mode. Under a second explicit offline-only selector, resident warm routes
  instead use mode 3 (L1-authoritative/no GDDR writeback). This prevents a
  stale or partially committed position from selecting cached state; it does
  not itself prove the L1 pages survived a reset or authorize enabling the
  experiment in live Work.
  The worker consumes the page map from its already-validated descriptor,
  avoiding a separate peer-table write.

This closes only the immutable package/startup serialization seam. It does
not change the status above: the experiment is not selected by the native
kernel or Work role, the deterministic addresses have not been backed by a

2026-11-15 L1-authoritative no-writeback experiment
-------------------------------------------------
Added an isolated mode-3 candidate for resident GDN state. Unlike warm
write-through mode 1, mode 3 reuses the mapped L1 state and suppresses both
GDDR state reads and the 32-KiB next-slot writeback. Spill rows remain mode 2
and retain their GDDR read/write path. The candidate is rejected unless the
explicit `PIONEER_Q38_GDN_L1_NO_GDDR_WRITEBACK_EXPERIMENT=1` selector is built
alongside the scattered-state experiment; Work, validation, native and kernel
roles remain compile-time excluded.

The emitted redistributed worker simulation passed 161 exact-output positive
cases over all 96 half-heads, both state slots, seven banks, four non-resetting
16-step state chains, and an isolated spill case. Warm residents used 7 worker
packets (7 reads, 0 writes), versus 9 packets (7 reads, 2 writes) in warm
write-through; the spill path remained 11 packets (9 reads, 2 writes). All
8,256 output/state words matched the independent reference, and 4,137 injected
fault cases passed without later NoC/SFPU/publication. The separate baseline
scattered build passed 161 positives and 4,138 fault cases. This proves only
the worker-level offline behavior. L1 is the sole state authority for resident
rows in mode 3, so any interruption invalidates that inference session; it
does not preserve GDDR rollback/resume state. No P100A latency or Qwen token
rate was measured.

2026-11-15 matched worker-count comparison
------------------------------------------
The no-writeback runner now executes the same emitted worker twice with the
same deterministic half-head, inputs, and initial state: warm write-through
mode 1 versus warm L1-authoritative mode 3. Both produced identical 8,256
state/output words. The simulator counted 259,612 RV32 instructions and 9
packets for mode 1, versus 197,086 instructions and 7 packets for mode 3
(62,526 fewer instructions, 24.08%). This is evidence that the worker's
mode-3 control/data path does not erase its transfer-count advantage through
extra emulated RISC work in this fixture. It is not Blackhole cycle timing,
GDDR latency, aggregate model timing, or a tokens/sec prediction; native owner
integration and a matched physical Qwen benchmark are still required.

The same test also runs a complete 96-task layer-40 cohort using the actual
allocator map. It resolves 95 resident routes and one spill route. All 96
write-through/L1-authoritative pairs produced bit-identical state and output.
The simulator counted 25,001,329 RV32 instructions and 866 packets for
write-through, versus 19,061,359 instructions and 676 packets for
L1-authoritative mode (5,939,970 fewer instructions, 23.76%). The spill
worker remained in GDDR mode in both runs. This is a stronger worker/cohort
comparison than the single-half sample, but still excludes layer scheduling,
other Qwen operations, native allocation/ownership, silicon timing and full
model throughput.
