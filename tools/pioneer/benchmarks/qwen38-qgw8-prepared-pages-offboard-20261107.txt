QGW8 converted-page preparation, November 7 2026: OFFBOARD ONLY
================================================================

This isolated proposal routes the output head to BFP8, FFN layers 50-60
to BFP8, remaining FFN layers to BFP4, and other learned weights to their
original format. Its read-only adapter binds the authenticated original
source and relocated plan, refuses unavailable or changed sources and caches,
and stages reads before publishing. Its full converted-stripe preflight
checks 1113 BFP4 FFN, 231 BFP8 FFN, and 7 BFP8 head fragments.

The existing CPU-only FFN preparer now has distinct explicit QGW8 options;
the previous 13-layer options retain their original behavior. A separate
CPU-only head preparer checks the full same-open model hash and prepares or
verifies all seven head cache entries, using an independently keyed converter
fingerprint. Neither preparer is integrated with Work or the native uploader.
The BFP8 preparer also supports a separately built --qgw8 selection: it
reuses the frozen conversion recipe but selects only 33 tensors (layers
50-60) rather than 39. Layout arithmetic shows this avoids converting
568197120 bytes belonging to the six unused layers 48 and 49 tensors. This
is potential preparation work avoided, not a measured load-time speedup.

Tests use fake complete-model sources and caches to exercise routing,
boundaries, preflight coverage, changed inputs, failures, atomic destination
and role guards; actual model source types are compiled. Separate existing
synthetic-data tests exercise the real head converter and cache. No full real
model was converted for this layout, no new driver was installed, no P100A
computation was performed, and no QGW8 inference or tokens/sec was measured.
Both CPU-only preparers also cross-compiled for RISC-V Haiku; they have not
been installed or run on the Pioneer.
An isolated CPU-only QGW8 preflight now retains the authenticated original
and checks the three dedicated prepared-cache formats together. Missing
directories are refused without creating them; existing-only cache opens now
avoid a previous mkdir race. Synthetic routing/role tests, real synthetic
cache tests, the old hybrid-preflight regression, and Haiku cross-builds
passed. The new preflight has not been run on the real model or real caches.
Its head converter fingerprint is now
e0e45dce6f1d95124aaeb956e2ee4076aff5b11d35d8079e205054cf33cf316f;
the preceding preparer binary's different fingerprint must not be mixed with
this preflight. Rebuild the head preparer with the same sources as preflight.

The existing span-packet builder now also accepts a separate explicitly
selected QGW8 plan; its default remains the prior 13-layer plan. With the
actual QGW8 prepared-page router over fake sources and transport, it checked
all 3551 weight fragments and 22035 packets, totaling 21167624192 synthetic
bytes. The old plan rejects these pages before the first transport call;
bad geometry and uncertain transport responses stop without retry. The real
GGUF/cache page-source and packet-builder types also cross-compile together.
This is NOT a card upload: the existing native session and receipt ledger
remain fixed to the older layout. A format-bound owner/receipt and a new
qualified runtime are still needed; presence-only ledger entries do not
prove which format was uploaded. The old driver must not accept this layout.

Non-loadable kernel inspection follow-up: a separate fixed-size QGW8 layout
records explicit original/BFP4/BFP8/head-BFP8 encodings and matches the host
proposal on all 4678 parts and seven banks. A separate QGW8 receipt checks
22035 ordered extents against a synthetic ledger and owner/FD/team/generation,
refusing altered/extra ledger entries and quarantining uncertain cases. Both
compile as freestanding RISC-V objects, with maximum individual static frames
192 and 880 bytes; neither object is a loadable driver or attached to a
running driver. The legacy receipt's independent tests also passed.
The format identity is a DECLARATION checked against geometry and host page
hash bookkeeping, not cryptographic model authentication, conversion proof,
or verification of card memory. No physical test or execution is implied.
