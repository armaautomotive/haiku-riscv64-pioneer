Qwen 27B: two activation rows sharing one exact Q4_K weight panel
==============================================================

The existing raw Q4 projection uses one SrcB row per token; the other
rows do not contribute useful activation results. The documented
non-broadcast Tensix MVMUL multiplies eight activation rows by the same
16x16 SrcA weight panel:
https://github.com/tenstorrent/tt-isa-documentation/blob/main/BlackholeA0/TensixTile/TensixCoprocessor/MVMUL.md

This isolated RV32 image fills rows 0 and 1 with two different
activations and leaves 2..7 zero. It reads both signed integer dot rows
after the actual final drain, applies the old Q4 coefficient, minimum
and signed activation scale independently, and accumulates each output
in the old FP32 operation order. This covers all sixteen K16 panels
of one 16-output/K256 GGUF Q4_K block. This first test does not cover
Q8/Q6 or a full-width model projection. It uses the original four fidelity phases,
not a new or approximate numerical format. Each panel still unpacks
the single weight tile once; the second token does not issue another
matrix multiply. Publication happens only after both outputs are ready.

The actual emitted RISC-V instructions passed the existing Tensix
instruction simulator on 24 different blocks with signed/boundary
scales: 768 bitwise-identical output words compared with two executions
of the pinned single-token control. The control also passed independent
dequantized-double comparison. Descriptor/non-finite/operand violations
and deliberately duplicated activation rows were detected in the 274
negative fixtures. The test checks disjoint writes, exact input/weight
preservation, 16 weight unpacks, 64 matrix issues and no NoC/memory
transport. No timing hardware or silicon behavior is simulated.

  python3 tools/pioneer/tests/run_pioneer_q38_two_token_q4_tests.py SDK NEW_OUTPUT [MODEL_GGUF]

This rebuilds the original block byte-for-byte, pins the 4,068-byte
candidate text, and runs both images under ASan/UBSan. The image rejects
native, kernel, Work, CPU reference and fast-math role combinations.
Candidate text SHA256:
c11734ef8e5aa76d4d47d7a2bad84b0c4073005a799b57b6affc2a43b57a1226.


Full-width streamed image
-------------------------
A separate Q8T3 image reuses the same two-activation math at all three
full model widths, for one 16-output Q4_K shard per run. The input and
scales have separate fixed bounds, and the job seals the exact projection
shape and bank. The controller confirms the caller's read-command route,
size, destination and flags without reprogramming them. Every actual
request observes an idle command/FIFO, verifies its expected address and
counter deltas, and rereads the command after completion. No output is
published on a failed or uncertain weight transfer. A future native
parent still owes real immutable-input, weight extent and NoC ownership.

The linked RV32 instructions, exercised on a simulated fabric with delayed
responses and counter wrap, matched 32 output words at each width against
two executions of the original pinned one-token stream. K5120 used 20
reads instead of 40; K6144 used 24 instead of 48; K17408 used 68 instead
of 136. These are simulated weight requests for exact same-weight pairs,
not DDR bandwidth or elapsed time. All 36 malformed and completion
fault cases stopped without publishing either row or retrying. These
included bad ranges, mismatched bank/byte count, nonempty FIFO, and
first/middle/last dropped replies, counter deltas, command and job changes.

The same test command rebuilds and runs these images, preserving the
old local and single-token stream pins. Streamed two-row text is 5,576
bytes with SHA256
fd6c8b885c84bda45093b28b2fc0cb0a3a8934edc60258852e10700666db280b.

Paired vector affine
--------------------
The vector path can now decode the original Q4 metadata once and
populate both activation rows as it transposes the existing coefficient
and minimum vectors into Dst. The two scales are broadcast into separate
subrows once per K256 block. Input sums are independently converted to
FP32 once per panel. The multiply and add sequence remains nonfused and
ordered as before. Each existing even/odd SFPU pass now accumulates both
token rows; the other two subvectors stay zero. There are no RISC-V reads
of intermediate dot or affine values in this arithmetic helper.

The command observer ran 21,696 panels across K256, K5120, K6144 and
K17408. It verified 694,272 bitwise-identical row/column results against
separate scalar Q4 calculations, including different scales for the two
rows, signed zeros and finite half subnormals. It also verified 1,356
single prefix imports, untouched zero padding and 12 inert refusals.
The existing linked vector92 worker passed its original binary/ELF pins
without any change. This is a command-model result: the paired helper is
not linked into a worker and has not run on silicon.

  c++ -std=c++17 -O2 -g -Wall -Wextra -Werror -ffp-contract=off \
    -fsanitize=address,undefined tools/pioneer/tests/pioneer_q38_two_token_q4_affine_test.cpp \
    -o /tmp/pioneer-q38-two-token-q4-affine-test
  UBSAN_OPTIONS=halt_on_error=1 /tmp/pioneer-q38-two-token-q4-affine-test

Linked full-width vector image
------------------------------
The distinct Q8T4 test image now connects the paired helper to the packed
Q4 vector decoder, not the older scalar unpack and affine loops. It
initializes both physical halves of the vector scratch before any partial
store and clears only the matrix dot rows between panels. One native
integer MVMUL pair (fidelity phases 1 and 3) evaluates both inputs.
The RISC-V worker still sets up the pipeline and sums the activation
operands. They do not decode Q4 weights or process per-panel matrix results.
Only the final, finite two rows are exported. The streamed control keeps
the original four phases and remains byte-for-byte unchanged.

The linked instruction simulator verified all 32 outputs at each width
against two runs of the pinned one-token stream. It observed:

  width    reads vs controls    matrix issues vs controls
  5120     20 vs 40             640 vs 2560
  6144     24 vs 48             768 vs 3072
  17408    68 vs 136            2176 vs 8704

Those matrix counts combine sharing and the existing exact two-phase Q4
optimization; two invocations of an already two-phase path would use
twice the paired count. No timing or decode-rate gain is implied. Eight
negative controls covered a wrong role, lost reply, changed descriptor,
non-finite weights and final values, missing scratch initialization and
dot clears, and a duplicated input row. The five-image ASan/UBSan suite
also preserves all four existing image pins and rejects 13 illegal role
combinations. Q8T4 fits within the original 8192-byte view: 7,784 bytes,
SHA256 75555b9c80398a7aa760a2d097512ed983c5125cf9c6a4d97a71c68bd2ccbe5d.

With the actual Qwen3.8-27B-Q4_K_M GGUF supplied read-only, the suite
also matched both results bit-for-bit for four real weight shards:
token_embd.weight at K5120 (rows 0..15 and 248304..248319) and
blk.0.ffn_down.weight at K17408 (rows 0..15 and 5104..5119).
K6144 was tested synthetically; this file had no matching Q4_K tensor
at that width. Activations and card timing remain synthetic/untested.

Next qualify a physical same-weight, two-activation comparison, with
exclusive worker ownership and explicit stop/restore. The linked image
serves one 16-output shard, not a whole-model trial. Separately the
request scheduler must preserve causal KV, recurrent state, and the
single-token fallback. Two known inputs can serve prefill or independent
requests; single-request decode requires a real draft/verification
scheme with independently correct state handling. This is not speculative
decoding, a throughput or latency estimate, or an installed driver.
