----------------

Readiness diagnostic follow-up, November 16
-------------------------------------------
The Pioneer remains reachable over strict-key SSH and reports the restored
stable041/gen4 record, 64 CPUs, and 137,034,936,320 bytes total RAM. Implemented
an opt-in worker diagnostic with independently timed vocabulary load,
prepared-Q4 cache preflight and metadata-only PCI probe. When built with
`--readiness-diagnostic`, the prepared-cache loop also prints a progress
marker every 64 original plan-part indices. The mode has no Generate call,
does not create an inference context, and the only device operation is the
existing metadata probe after preflight. On Haiku it measured vocabulary
authentication 311.872 s and read-only prepared-Q4 preflight 572.879 s for
20,470,759,424 planned bytes. The metadata probe then failed
`full_offload_unavailable` in 0.003 s against stable041, which does not support
the tag97 prepared-Q4 profile; no inference occurred. These timings show the
current worker's CPU readiness path is under 15 minutes. The exact older worker
used by the timed-out tag206 attempt then ran against stable041 under a
Load/Unload-only client. It exited with the stable-profile error after 1,399s,
514s slower than the current worker's measured authentication+preflight
(884.751s), but below the former 1,800s deadline. Its client had no Generate
send path. This still does not explain the 1,800s wait under tag206; the
candidate-specific metadata path remains untested. The candidate stage is
still spent; no TPS result was produced.
