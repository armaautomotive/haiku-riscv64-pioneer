PROVEN SOURCE DEFECT / NARROW FIX
clear_page -> vm_memset_physical -> actual RISC-V MemsetPhysical ->
user_memset -> validate_memory_range. The old predicate checks exclusive
address+size overflow, so fffffffffffff000 + 4096 is rejected. clear_page
ignored that failure, allowing an uncleared page to be treated as cleared.
This is a reproduced defect consistent with the malformed last-page table;
it is not proof that every historic kernel/network stall has this cause.

Validate the LAST ACCESSED BYTE instead, treating zero length as empty;
true byte-range overflow and user/non-user endpoint crossing still fail.
clear_page now panics with the physical page and status if clearing fails,
rather than silently supplying uninitialized memory. No RAM/CPU reduction,
mapper relocation, nonleaf permission relaxation or retry-mask workaround.
RISC-V generic memset/memcpy are count-based; emitted memset's optimized
aligned loop uses equality, not ordered comparison with a wrapped end.
