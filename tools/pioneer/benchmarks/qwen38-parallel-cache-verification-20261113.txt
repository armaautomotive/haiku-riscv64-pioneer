Experimental parallel cache verification, November 13

The unchanged cache format records a SHA-256 for every 64 KiB chunk and a
second SHA-256 for the complete tensor. The opt-in
PIONEER_CACHE_PARALLEL_VERIFY=1 build computes the ordered whole-tensor hash
on one helper while the caller checks the same immutable chunk. Both checks,
file-identity checks, progress ordering and clean failure remain required.
The caller waits before reusing the buffer. If thread creation fails, it uses
the original serial hashing. Ordinary builds do not enable this candidate.

Serial and parallel builds passed the same 48-case host disk-cache fixture
under ASan/UBSan, including corruption and source/recipe checks. The parallel
fixture also passed the host ThreadSanitizer run; this is not a proof against
all possible races or a Haiku runtime test. The exact
reviewed-reader cache recipe compatibility test passed and retains the
existing cache key; changed source inputs outside the pin are refused.
The opt-in cache source also cross-compiled for Haiku RISC-V with the pinned
SDK. It has NOT run on the Pioneer, and there is no timing, loading speed,
inference speed, numerical-quality or 20-token/s claim. The helper's per-entry
thread startup and synchronization may outweigh any hashing benefit; compare
matched real loads before considering installation.

The isolated Assistant builder now accepts
PIONEER_Q38_PARALLEL_CACHE_VERIFY=1 only with the lossless-cache Work worker,
and rejects combining it with the ongoing Work phase profile. The separate
Haiku RISC-V worker cross-linked successfully; its SHA-256 is
8f18a95e9baf86a4fbec80a29be97abb95eea25ae3b4933d5dafb66b054d554b.
The combined profile/parallel build was refused with exit 2. This binary was
not installed or run, and the ordinary builder leaves this option off.

Local synthetic timing follow-up: on the Mac, the committed benchmark used
one 128 MiB cache entry, four warm serial, four parallel, then four serial and
four parallel checks. Serial samples ranged 0.118831-0.121874 s; parallel
samples ranged 0.109227-0.128676 s. Most parallel samples were slower and
the fastest was an outlier. This is not an improvement demonstrated even on
the Mac; its SHA implementation and storage are not the Pioneer's. The
fixture measures full verification only, not upload or token generation.

The synthetic benchmark now also cross-links for Haiku RISC-V in both modes.
Serial SHA-256 e9651764ce7dcf82646d301fe5c051309b7ae585bcb1b5e951974539ac8469b4;
parallel SHA-256 8a44ed0739a53e2ffc91e8967a1eaa4ddba1ab50f8b0af26de99766383a2600d.
These binaries have not run on the Pioneer. Their fixture is synthetic and
must use a fresh isolated temporary directory, never the model cache.
