QGW8 emitted head worker with real weights: offline simulation
===============================================================

Purpose: narrow the severe tag128 first-token mismatch before another
physical experiment. This is NOT a P100A run, a full-model test, a quality
pass, a Work-mode change, or a performance measurement.

The original 27B GGUF was authenticated against the existing full SHA-256
c600de0300ae8a0eb3a6c0b8b5561b8b96f16bd2c863c2a66c42de29d391a747.
Four actual output.weight bands (first rows 0, 70240, 108128 and 248288)
were freshly converted to BFP8. The middle bands contain the reference token
70253 and the physically observed token 108133. The exact pinned QGW8 RV32
worker and BFP8 leaf executed under the existing simulated NoC/FPU, with the
prior 64-layer completion injected and a synthetic BF16 input. A separate
software arithmetic observer predicted every row; all 128 output words and
the four local argmax receipts matched exactly. Actual process exit was 0.

The per-band argmax rows were 13, 70256, 108136 and 248302 respectively;
these are results for synthetic input, not model-generated tokens. This test
does not use the real normalized hidden vector, card DRAM, physical matrix
engines, ROOT-to-worker lifetime, actual upload or real model execution. The
conversion and software arithmetic implementations share code lineage with
other project tools. Passing therefore does not rule out incorrect physical
data, hardware behavior, other vocabulary bands, a cross-worker issue, or an
earlier-layer error. No Work path or GPU state was touched.

Reproduce on the local Mac with pinned worker/leaf directories and original
GGUF using tools/pioneer/tests/run_pioneer_q38_qgw8_real_head_worker_test.py.
The runner authenticates every used emitted worker section and leaf image;
the diagnostic separately authenticates the full same-open model.

Pinned CPU-reference hidden follow-up
-------------------------------------
The separate converted-FFN CPU hidden snapshot, SHA-256
ce1ed4778227d6deb4bc0fd85440facf2a680c7d60b2e7d92c60e74abd73c98a,
was authenticated and shape-checked. Its converted final hidden vector was
normalized with the authenticated original output_norm weights and supplied
to the same emitted-worker simulation. All 128 row outputs matched the
separate CPU observer, including local argmax 70253 in the 70240..70271
band. The other local argmax rows were 23, 108147 and 248301. Actual process
exit was 0. These are band-local selections, not a full-vocabulary result.

This is CPU-reference data, not the missing physical snapshot, and the
network, memory and matrix hardware are still simulated. It does not establish
that real card hidden values, upload, scheduling, or matrix arithmetic match.
No Work, hardware or tokens/second claim follows. Pass the optional absolute
cpu-hidden.bin path as the fourth runner argument to reproduce this mode.

Private head-band diagnostic data preparation
---------------------------------------------
The optional sixth command-line argument to the C++ diagnostic (fifth runner
argument after program name) names an existing private mode-0700 output
directory. After all four real-weight worker comparisons pass, it creates
exclusive, mode-0600 private data/metadata headers for bands 0, 70240 and
108128 using the pinned CPU-reference normalized input. It does not install,
open the card or create a driver. An attempted second export to the same
directory failed without changing either header's hash. Data and binaries
containing model weights must never be checked into Git or distributed.

The actual emitted BFP8 leaf was separately simulated using the exported
header's GDDR and input layout; all 64 expected words for each of the three
samples matched (192 total), and the process exited 0. This confirms the
exported representation is usable by the existing simulated leaf, not that
the physical card has run this new workload. A new uniquely identified driver,
independent source verification, guarded lifecycle, tests and physical
qualification are still required before this can be run on hardware.
