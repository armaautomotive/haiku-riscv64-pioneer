QGW7: hybrid projection plus matrix-engine attention
=====================================================
November 7, 2026. OFFLINE experiment only, not a driver, Work/Assistant mode,
full model, physical-card execution, quality assessment, or speed result.

The returning BF16 matrix attention capsule is linked into the experimental
hybrid BFP4/BFP8 persistent worker. It uses distinct QGW7 external and QDM2
inner-frame identities: the simulated QGW7 dispatcher refused QGW5 boot
and job records before any transfer. The previously pinned QGW5 image was
rebuilt and checked unchanged. The new dense code fits in the QGW5 proposed
16 KiB dense-code snapshot range; its QDM2 scratch addresses also lie within
the proposed peer snapshot. That is geometry, not evidence of native
ownership, lifetime safety, or safe installation.

The actual QGW7 RV32 image ran BFP4 synthetic projections through its real
dispatcher for two matrix widths and peers 1/119. A separate TEST-ONLY image
changes the BFP8 layer mask to layer 0 so the actual BFP8 leaf can be tested
without fabricating 48 layers of model history; it passed the same cases.
Both formats validated receipts and faulted on malformed jobs; QGW5 identity
was refused. The test-only mask is not a real-model worker.

An additional instruction-level simulation retained a single worker's
registers, tensor configuration, source banks, L1 and NoC counters across
three genuine BFP4 down-projection jobs for layers 0/1/2, all three QDM2
attention phases at layer 3 with nonzero query/key and one current token,
and another BFP4 down projection at layer 3. The independent attention
score/partial-value and final projection output checks passed. Observer-only
bookkeeping counters were rearmed between synthetic projection jobs; the
simulated hardware state was not reset. Dense writes were checked against the
proposed peer snapshot. This covers one worker and a one-token attention
frame, not a full layer sequence, prior-token NoC attention reads, the ROOT,
global reduction, actual weights or real model inference.

Integration testing caught two generated calls into legacy byte-at-a-time
copy/set routines: a local route table and a zero-initialized descriptor.
The QGW7-only path now uses direct route selection and volatile word stores.
The new globalworker and dense sections have no byte-store instructions or
calls to those routines; the unchanged ancestral GDN object still contains
byte-copy fallback code, whose reachability and silicon behavior are not
established here. One attempt to start BFP8 directly at layer 48 correctly
faulted because the worker had no prior layer history. The test-only layer-0
mask was used instead, and does not establish the real layer-48 path.

Reproduction: build a QGW7 image and a separate --test-bfp8-layer0 image
with build_q38_hybrid_matrix_attention_worker.py; build independent BFP4 and
BFP8 leaves; then run tests/run_pioneer_q38_hybrid_matrix_attention_tests.py
with SDK, QGW7, BFP4 leaf, test-only QGW7, and BFP8 leaf directories. The
runner verifies the ELF/section pins and runs under ASan/UBSan. The 31-case
tests/pioneer_q38_hybrid_matrix_roles_test.py checks role and identity
refusals. Existing standalone QDM2 tests continue to cover 24 simulated
partitions and a multi-chunk frame, separately from this transition test.

Coordinator integration, offline only: an exact --hybrid-matrix-attention
build profile propagates both QGW7 and QDM2 defines to the real linked ROOT,
recurrent and dense components. Two independent builds produced identical
files (program.elf SHA-256 f9be15a56b126b8809880eb3dee32217c4c6cfa41f7e546714add7747b814c83).
The existing QGW5 ROOT rebuilt with its original pinned files. An actual RV32
ROOT function simulator generated 72 projection jobs across both linked
components, formats, widths and boundary layers; the job layouts matched the
independent canonical planner, passed QGW7 worker shape checks and rejected
old QGW5 identities and mutated manifest data. This exercises functions,
not the whole ROOT lifecycle or its dense-attention transfer path. Build
profiles and the shared grammar reject QDM2 with the old worker identity.
Reproduce with tests/run_pioneer_q38_hybrid_matrix_root_tests.py SDK and
tests/pioneer_q38_hybrid_matrix_roles_test.py SDK. Neither build is a native
or Work-mode authorization.

A focused coordinator-to-worker simulation now executes the actual linked
ROOT DensePartitionRoot::Job instructions and delivers their three phase
jobs to the actual QGW7/QDM2 worker, after three synthetic projection jobs
and before another projection, without resetting its simulated registers,
matrix state, banks, L1 or NoC counters. Independent checks covered score,
value and subsequent projection output. An actual QGW5 ROOT job was rejected
by the QGW7 worker before any new NoC request or matrix operation. This is
one peer and one current token: its frame and input were synthesized and the
test harness directly delivered the ROOT's jobs, rather than executing the
ROOT's transfer, wait, global reduction or real NoC paths. It is not a full
coordinator lifecycle or multi-token result. Reproduce by supplying SDK,
QGW7 worker directory and BFP4 leaf directory to
tests/run_pioneer_q38_hybrid_matrix_root_tests.py; the runner checks their
image hashes, rebuilds both ROOT identities and uses ASan/UBSan.

A subsequent one-peer synthetic-fabric test executes the actual linked
QGW7 ROOT Transfer instructions and the actual worker instructions, after
three real simulated projection jobs have established worker history. The
ROOT transfer code sends the dense frame, query, current K/V, two parameter
frames, three jobs and doorbells; it then reads boot/status/doorbells,
three-phase internal jobs and receipts, and the 12 KiB partial result. The
result matched the synthetic reference. The 29 modeled packets use checked
ROOT source/counter/command seals, and an injected command-readback fault
stopped the ROOT before issuing an additional packet. The fabric completes
packets synchronously and the fixture supplies ROOT private frame and inputs;
that initial test did not execute ROOT Launch/Snapshot/global reduction,
96-worker coordination, prefix-KV NoC reads, full token or physical silicon.
The same root-test runner executes this case when the worker and leaf
directories are supplied. This is not a Work-mode or hardware speed result.

The same one-peer test subsequently added the actual linked ROOT Snapshot
routine after each of the three phases. Its Wait, boot, frame, job,
doorbell, summary, counter, parameter and local-result checks run against
the real simulated QGW7 worker. The initial worker counter baseline comes
from that worker after its three simulated projection jobs, not a newly
invented worker history. Injected receipt and counter corruptions each
caused the actual ROOT to fault without issuing a later packet in the
faulted test branch; command-readback corruption was also refused. The
fabric, reset/PC-register responses, initial ROOT frame and inputs remain
synthetic. One peer and one current token do not qualify the 96-worker
Launch/global reductions, prefix-KV traffic, full model or physical device.

A separate offline test executes all 68 actual QGW7 gated activation
producers and transports their emitted BF16 bytes through a synthetic fabric
into the input of an actual QGW7 BFP4 full-K down projection on worker 1.
That worker keeps its own real simulated producer/NoC/register history;
attempting its down projection without its producer is refused before any
matrix operation. All 64 output words match a post-hoc calculation from
the emitted input and independently unpacked test weights, using the same
instruction arithmetic model as the matrix observer. It does not verify
the activation against an independent oracle, execute the real ROOT
transport, run other workers' down projections, reach attention, exercise
the real model, or establish hardware behavior. It is included in the
same ASan/UBSan runner when the worker and leaf are supplied.
