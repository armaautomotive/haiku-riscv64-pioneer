Converted-weight disk cache: CPU implementation and bounded verification
=======================================================================
2026-11-03. Source baseline 9c492534ef64ce242788366f0ccda624716c7c13.
This checkpoint adds an experimental native-weight converter and generic
persistent derived-weight cache. It does NOT change the active GPU driver,
Assistant selection, original comparator, tolerance, boot, CPU or RAM code.
No new hardware inference, model-quality pass or tokens/sec gain is claimed.
The existing ~0.1643 tok/s diagnostic and unmet 20 tok/s goal are unchanged.

Implemented, not yet an enabled native inference path
-----------------------------------------------------
CPU conversion of Q4_K -> BFP4_B and Q8_0/Q6_K -> BFP8_B native 32x32 tiles;
immutable derived payloads keyed by authenticated original SHA-256, complete
source-fingerprinted conversion recipe, tensor ordinal and byte length.
Dedicated private marked directory, read-only owner single-link entries,
whole/index/per64KiB SHA-256, full verification on every open, affected-chunk
rehash before atomic Reader publication, private fsynced staging and atomic
rename. Invalid owned entries rebuild; unsafe links/permissions refuse.
No broad deletion or automatic eviction. Requires entry size plus 2 GiB
headroom. Source/produce failure BEFORE publication preserves the old entry;
a later cancellation can leave a complete published entry but returns no
Reader. Directory fsync is best-effort, not a power-loss certificate.

Native block-float is a different numerical representation (requantization),
NOT the current lossless packed layout. Neither hardware nor Assistant
selects these bytes. Native math/format and model-quality qualification,
bank/arena planning and loader integration remain before Work promotion.
Cache integrity is data, not device authority or malicious-same-user proof.
