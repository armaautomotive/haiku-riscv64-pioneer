QGW8 all-layer trace ROOT: isolated offline build, 2026-11-09

The physical tag129 run found a substantial final-hidden mismatch, but it
captured no intermediate layers. This experimental ROOT variant copies each
of the 64 just-returned layer hidden vectors for position zero to a separate
workspace slot before moving to the next layer. It uses the existing ROOT
scoped transfer/counter path, 16384- and 4096-byte chunks, and reserves
64*20480 = 1,310,720 bytes of address geometry. The chosen proposed slots
follow the token-record extent and fit within the existing workspace extent.
They are NOT yet an authenticated allocation or a native-owned trace buffer.

This is a build-only inspection image, NOT a driver, program-ownership
grant, trace readout, CPU comparison, Work/Assistant feature or speedup.
It MUST NOT be installed or run on hardware. Before any hardware use, prove
full workspace ownership/initialization, no alias with all live extents,
source immutability, write completion and visibility/readback, exact layer
association, cancellation/fault/cleanup behavior, combined stack, bounded
owner lifetimes and a separately pinned native/client protocol. The earlier
physical cancellation experiment failed and quarantined the card; this
variant does not assume that mechanism works or reuse it as an authority.

The unmodified QGW8 ROOT rebuilt to its prior ELF SHA-256
8b7bac64e64d963e729e347a209c3ca4be951992aa924ead0c48d97e0e79478f.
Two same-SDK trace builds matched ELF SHA-256
a103f6d5134355ba7d0af0479e7f09f34e31591850fa2fc566abfc079821e402;
their returning-layer and feedback components matched the old ROOT objects.
The ordinary native-candidate generator rejected the modified ROOT before
opening its worker input. Role checks reject native, kernel, Work, other
experiment roles, zero and late selectors. The actual emitted trace helper
was executed in an RV32 simulator with Owner and Transfer intercepted: all
64 slot addresses at both workspace extremes and four state refusals passed.
This tests the compiled helper's call geometry, NOT the actual NoC transfer,
full ROOT execution, model values, device safety, or physical timing.

Follow-up: the RV32 test now also executes the linked Transfer routine, with
Owner and Scope intercepted and an immediately completing synthetic NoC.
It copies synthetic 5120-word states into the expected slots for boundaries
0, 31 and 63; an injected command-register corruption causes a fault before
any later transfer. The old address/role/guard tests still pass. This is a
mock of NoC registers and does NOT prove real ordering, source lifetime,
ownership, fault recovery, full ROOT lifecycle or physical safety.

The mock was then changed to delay each transfer for four busy-register
reads. The linked routine again copied the expected synthetic contents for
boundaries 0, 31 and 63 and performed no new transfer after a corrupted
command. A permanently busy synthetic transfer reached the bounded fault
path without issuing a subsequent packet or publishing the destination.
This is still synthetic NoC behavior and does not prove hardware safety.

Separate trace program DATA
---------------------------
The pinned trace ROOT and unchanged QGW8 worker can now be packaged as a
distinct offline QTPA family, selected only by an explicit trace-programs
inspection role. Two independent generated headers match SHA-256
60803a2dfe96d9e45ec5da6f71f795b2ca2eb1cf82c013ec1a42841bfb517bd1.
The generator authenticates every input section and the complete ELFs, and
tests compared 3,608,359 emitted words over all 120 worker layouts. Existing
QGW8 candidate DATA stayed byte-identical; its generator rejects this trace
ROOT. Native candidate tag128, hidden tag129, fake native, CPU validation,
Work and other conflicting roles reject the trace selector, including a
defined-zero selector. The previous QGW8 coarse-profile regression passed.

This packaging does not allocate or initialize the trace slots and has no
native driver, upload, readout, or hardware permission. It is not an
inference-speed result. Next work must establish those ownership and data
contracts and qualify failure recovery before any card operation.

Trace DATA geometry and ordered assembly
----------------------------------------
The ROOT's proposed slot constants are now shared with a fixed address
geometry helper: 64 boundaries, two chunks per boundary, 4096 and 1024
words. An offline assembler accepts only 128 ordered chunks associated with
one caller-supplied key and publishes a complete in-process copy only after
all have arrived. It fails closed on changed key, missing/out-of-order or
duplicate chunk, wrong length, null data and invalid workspace geometry.
The caller-supplied key is merely DATA correlation, NOT authenticated
provenance, driver generation, a held-owner proof or permission to read the
device. No native transport, FINISH, close or userspace fault handling is
implemented. A copy into an arbitrary user pointer is NOT claimed atomic.

Synthetic sanitizer tests covered 384 valid geometry cases, eight invalid
cases, ordered assembly, six malformed streams, output refusal and role
separation. The trace ROOT rebuilt byte-identically to the previously pinned
ELF; its emitted helper and delayed synthetic-transfer tests passed again.
These checks do not establish device ownership or real-layer correctness.

Private trace read inspection
-----------------------------
A new private read method can derive each trace chunk address from that
shared geometry, require the fixed completed terminal and drained records,
recheck the existing 120 held/source/counter guards, and stage a whole chunk
before publishing it to a trusted in-process buffer. Failures after entering
the read retain/quarantine the mock owner without retry or following IO.
This method exists ONLY in a fake-tag, non-loadable native inspection role:
there is no external control operation, real driver route, or permission to
open the card. The slots still lack a proof of allocation, initialization,
actual ROOT production and lifetime. Nothing is installed.

Tests extracted the actual new methods and existing guards into a synthetic
fixture: 256 ordered chunks with counter rollover and 30 early/fault
refusals passed, including command, source, clock, counter, terminal, boot,
copy-read and alias failures. Legacy and tag129 hidden-read mock regressions
each passed 1057 retained faults. The real fake-owner class compiled in the
Haiku RISC-V SDK, with the new method instantiated against compile-only IO;
its individual frame was bounded, not its combined stack or real IO path.
An ordinary tag129 driver rebuilt to the previous SHA-256
0b61c939d9b461a6c60e0d7f68a2c3bccac588ea052dc634d85b9a35d32b929f.

The first fake-owner compile rejected a reload macro required by its existing
inspection fixture; the guard was corrected while retaining the fake tag,
compile-only role and native/Work refusals. A subsequent attempt to
instantiate against the binding-only fixture failed because that fixture has
no runtime IO methods. It was replaced by explicitly non-callable compile-
only IO; the separate extracted-method tests use mock IO. Neither change is
evidence of an actual driver connection, card safety or throughput.

Offline DATA handoff
--------------------
A proposed fixed, pointer-free packet and one-outstanding-request handoff
now connect the extracted inspection reader to the ordered assembler in an
end-to-end 128-chunk mock test. Request identity, metadata, unused reply
fields and tail padding are checked, and any mismatch invalidates the data
assembly. Tests flipped every request/reply bit and exercised 1540 malformed
packet/lifecycle cases, raw non-finite DATA, and late or conflicting roles.
The existing tag129 hidden-read mock regression passed again.

The packet's caller-supplied key is correlation only. These checks do not
authenticate the source or prove the raw payload correct, and a same-shaped
altered payload cannot be detected by this DATA handoff alone. There is no
ioctl assignment, real driver handler, native/Work permission, completed
ownership proof, FINISH/close guarantee, or physical trace result.

Fake request/copy control inspection
------------------------------------
A fake-tag-only request handler now checks the fixed pointer-free packet,
credentials and same-context call scope before calling the trace wrapper.
It retains on uncertain successful-read reply shape or output-copy failure,
and clears its staging payload before attempting a failed response. It is NOT installed or dispatched
by the real driver: credentials, user copies, source and ownership in the
test are simulated. Tests passed 128 requests through the actual inspection
handler and context wrapper with a synthetic underlying owner, plus partial
copy, malformed request/reply, denied scope, and retention cases. They do
not establish real user-copy, full-owner, FINISH or physical safety. A
RISC-V SDK object also compiled with a bounded individual control frame;
this does not prove the combined kernel stack or real call path.

The offline assembler handoff now requires the caller to report successful
transport before accepting a reply. A simulated failed transport is rejected
even when the packet looks valid, and its assembly remains invalid. That
boolean and the source key are still caller-supplied: this is not proof of
transport or source authenticity. This closes no physical-access gate.

Post-run DATA comparison
------------------------
An offline comparator consumes the 64 ordered raw position-zero vectors,
requires an exact caller-specified SHA-256 and an explicit relative-L2
threshold, and compares them to the independently pinned original CPU
boundaries. It reports every boundary and the first threshold exceedance;
it does not use CPU reference work during inference. Its SHA-256 checks
file identity, not origin, completeness, layer association, or card
execution. This is not a numerical acceptance test: quantized converted
weights can differ from the original CPU model, and the threshold is a
diagnostic choice rather than an established correctness criterion.
Synthetic controls check indexing, boundary selection, finite values,
lengths, role separation and SHA mismatch. No actual trace was available.

Converted CPU layer controls
----------------------------
The separate full-model CPU diagnostic can now exclusively create a raw
64-layer converted-FFN reference after the original result matches its pin
and the converted calculation and head checks finish. It prints a digest;
the output is CPU reference DATA, never a device observation. The offline
comparator accepts this second reference only with an explicit matching
digest and reports its threshold exceedance separately from the original
model. A hash confirms file identity, not provenance or numerical validity.
Synthetic tests cover layer order, finite values, exclusive creation, alias,
shape, role and reference-hash checks. A real reference run completed with
exit 0. Its original-model pass matched the independently pinned CPU result;
both converted FFN and converted FFN+head selected token 70253 for the fixed
input. Its 64 converted layer outputs have SHA-256
cfe8aaf5e0877a2260c957b2d996ce4626be5779a038886f65934893aef93599.
The private local copy is generated.pioneer/qualification-inputs/
qgw8-hidden-reference.Yn7npdOx/converted-layers-v1.bin; it is not an
off-machine backup. These data do not establish P100A execution or speed.
An independent offline verifier checks that a completed raw export has the
correct length and finite values and that its final layer matches the
previously pinned converted CPU hidden snapshot bit-for-bit. That check
does not independently authenticate its other 63 layers or prove origin.
The verifier's synthetic refusal and success tests passed; the real final
layer matched bit-for-bit. The other layers' origin and correctness are
supported by this run but not independently verified.

Comparing the converted CPU data with pinned original CPU data gives relative
L2 0.0180785026009 at zero-based layer 0 and 0.318669482813 at layer 63.
An illustrative threshold of 0.1 is first crossed at zero-based layer 46.
This is conversion/arithmetic drift between two CPU calculations, not a
hardware result, causal localization, or a correctness threshold.
