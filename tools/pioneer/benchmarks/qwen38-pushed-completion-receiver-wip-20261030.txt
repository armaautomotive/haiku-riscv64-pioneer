Production-source experiment
----------------------------
--pushed-completion requires the entire existing worker-sealed-admission /
single-audit / precise / local-source / boundary / unrolled / FP32 profile
(and cancellation for the parent). The DATA selector chooses distinct
QGW3 worker boot/job grammar, including all 55 boot words. Existing native
contexts, fixed QTP2 DATA, worker image roles, CPU validation and Work roles
reject the new flag, even defined zero. Late profile changes are rejected.

After genuine prior admission of all119 workers, Projection::Run owns and
clears the active existing 0x118000 proof slots. It verifies the clear and
unchanged ROOT master/slave counters before sending jobs/doorbells. Incoming
256-byte payload + 4-byte commit messages are read locally with fences.
Each receipt binds the actual boot/source/job/layer/position/nonce and the
expected pre-push counters derived from the retained frontier and matrix
geometry. The normal arithmetic proof and output rows are still read from
the worker and independently checked. Gather no longer performs the old
remote status/reset/PC/boot/job/counter polling for active matrix workers.

Receipt counters establish an EXPECTED frontier including the two writes,
not a claim that a current physical counter was observed. The next Admit
still waits for genuine DONE/WAIT and reads actual physical counters before
another job. Admission of a previous matrix accounts for the two completion
writes when comparing its pre-push arithmetic proof to actual counters.
This changes fault-observation timing and is not an equivalent old audit.

The receiver checks all four incoming slave-counter totals and revalidates
every active receipt before and after scatter. Unexpected totals/marker,
stale nonce, changed payload or finite timeout park without a later packet,
retry, reset or cleanup. No new large L1 allocation is made; proof-slot
ownership is phase-exclusive. Native mapping/journaling remains owed.

Blackhole L0 is not coherent with incoming writes; fences are deliberately
used before polling/copying. Primary vendor source:
https://github.com/tenstorrent/tt-isa-documentation/blob/main/BlackholeA0/TensixTile/BabyRISCV/README.md#l0-data-cache
The HOST fabric models four direct-mapped 16-byte cache lines in these slots,
local-store matching-line invalidation, and actual-fence flushing. Raw NoC
writes do not invalidate cached lines. This model is not a physical cache
qualification or permission to alter a live hardware cache configuration.
