# Dense attention output-shard resident witness

This isolated, non-loadable experiment distributes each of the 16 query heads over seven or eight workers. Its 120 workers own disjoint 16-lane-aligned slices of the 4,096 attention output values. Every shard computes the entire score and denominator for its head, accumulates only its own lanes and writes the aligned slice. It preserves score and per-lane accumulation order without a cross-worker reduction. This deliberately duplicates the Q, K and V reads; for a given context, logical KV tile reads are 120/16 = 7.5 times those of the prior single-worker-per-head path. Hardware caching, contention, latency and throughput are unmeasured; this is not a claimed optimization. KV packing still uses 4 workers per operation.

The actual recorder emits stream version 4 and one shard invocation per core for each of the eight dense layers. Position patching and exact head/lane coverage were verified on every emitted record with synthetic layout; altered ownership metadata was rejected. The host shard worker matched separate host attention operators at positions 0, 2, 33 and 63 under ASan/UBSan, including multi-tile KV and a failed write. Host and device operators share approximation primitives. The resident simulator ran the compiled image with synthetic position 2/4 and 33/64 fixtures: all 120 workers completed the key-pack, diagnostic workspace copy, value-pack and attention barriers; all KV bytes and output storage matched the reference with maximum output error `1.86264515e-9`. The fifth record intentionally faulted and no completion candidate was published; it was not an explicit fleet shutdown. See `short.log` and `long.log`. No model weights, full dense layer or full model were run.

The RV32 dataflow and resident images linked only after excluding duplicate legacy attention-run code from this witness. Resident text is 57,048/57,344 bytes and dispatch is 28,368/28,672 bytes. Conservative stack estimates are generic `7968/8192` and dense-specific `5056/8192`, including 1,024 bytes allowance; neither is a whole-program proof.
