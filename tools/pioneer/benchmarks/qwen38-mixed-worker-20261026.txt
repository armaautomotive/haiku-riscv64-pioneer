Implemented
-----------
One genuinely new worker front end owns the boot record, full64-word job,
private monotonic nonce, physical source seal, and completion status. The
same live worker calls matrix, activation/input packing, Conv, paired GDN,
GDN output packing, and all three dense-attention phases. Attention RETURNS
instead of entering the standalone QDW1 STOP terminal. Local/global maxima,
scores and partial state persist between the phases. A completed phase3
allows a new layer/position frame, never a fresh boot or reset of history.

The old QFP2 records are INTERNAL arithmetic-call data only. The external
grammar is QMW1, not a retagged old native scope or caller-ready flag. Old
arithmetic translation units are separately recompiled as internal capsules
with s11 reserved. The new front end alone sets s11 to its private stack
snapshot; the packet seal alone reads it. The complete emitted disassembly
contains exactly those two s11 instructions. There is no writable global
or second public mailbox posing as a private descriptor/source snapshot.

Before/after packets, capsule hooks check the complete captured external
boot/job, current global doorbell and all16 physical source words. Existing
arithmetic descriptor/command/counter checks remain. The front end also
retains all8 counter words across idle/job boundaries; unexplained movement
cannot be absorbed as the next baseline. Words2/6 alias ONE physical counter.
No CPU numerical reference, CPU dot validation, host intermediate product,
PCI weight roundtrip, code reload, core reset or per-attention STOP is in
this new executable lifecycle. Matrix-call data still have their own bounded
debug/work selector; this is NOT an installed Assistant Work mode.
