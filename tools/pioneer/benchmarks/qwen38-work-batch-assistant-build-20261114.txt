Source audit of the current batch handler: it prepares one Q38 dispatch
lease and then invokes the ordinary `PioneerQ38DispatchRun` twice in
sequence. The second call can reuse the first call's exactly-matching
activation/scales via the kernel-private cache and omit their staging writes;
the descriptor/image setup, root start, compute, proof, and root stop still
occur twice. Therefore this is a host ioctl consolidation plus a possible
small input-staging saving, NOT one fused root launch or an all-card graph.
Its actual reuse-hit rate and elapsed-time effect require a full real-model
Pioneer run and remain unknown. The previous 0.200 tok/s baseline is not
updated by these offline tests.
