QGWD fixed two-token native candidate: compile-only checkpoint
=============================================================

The tag142 native role uses the previously tested QGWD ROOT and worker
images, with a distinct candidate program-data marker and driver identity.
Its protocol admits only the fixed input 248319 and exactly two requested
outputs. Work mode and CPU-reference roles remain excluded. The previously
tested tag141 remains limited to one fixed output.

Two independent program-data bundles matched SHA-256
f4bc8d499b2c12d381fb24ba3423af1fed6792fa94e52882eb627697d721a687.
Role, reload-identity and protocol-shape tests passed for both tags. Cross
compilation of both real native driver bodies passed, with bounded selected
stack frames; missing tag142 data markers and cross-role headers were refused.
The tag142 build script also refused the old tag141 program header.

Two independent clean tracked-source snapshots at commit 706f68574d, with
the same local generated configuration headers and SDK, linked byte-identical
candidate drivers, SHA-256:
fccf39747b740c886b2fa762fee0ded24a20c9975b4da538a850782e9c83ab1b
The same snapshot rebuilt the earlier tag141 driver byte-for-byte, SHA-256:
e8dbd864e01407d60e97922f0f47427e87b267997efa489b860391e07c3df5b3.
The first attempted snapshots omitted a tracked PCIe header and failed before
linking; the header was added to each snapshot and new output directories
were used. No existing data or output was removed.

No tag142 driver has been installed, executed, or tested with a model. A
matching driver/client is not by itself authority to run the hardware. This
is not a quality result or a performance result. The two-token client
remains separate from Work and from CPU validation.
