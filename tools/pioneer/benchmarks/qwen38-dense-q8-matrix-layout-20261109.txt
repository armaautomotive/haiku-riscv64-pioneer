Dense Q8 Q/G/K/V matrix layout feasibility, 2026-11-09
=======================================================

The current QGW8 full-card projection controller dispatches the 16 dense
layers' original Q8_0 query/gate, key and value matrices to the existing
FPU worker path. This proposal changes their storage geometry to BFP8
matrix tiles, while retaining the existing QGW8 bank assignments and the
other proposed encodings. On the fixed canonical 27B layout, all 336
fragments / 229376 rows pass 32-row alignment and fit in the seven existing
3-GiB bank capacities. Their allocated size decreases by 73400320 bytes
relative to the existing QGW8 proposal. This is a layout feasibility
result, not a model conversion, inference execution or performance claim.

The plan requires exact Q8 source type, row bytes, row ordering, fragment
coverage and capacity. An unready source and eight malformed-source variants
were refused without modifying the previous output. The implementation is
explicitly offline and rejects native, Work and CPU-reference roles. A
usable matrix path still needs authenticated conversion/caching, a driver
owner and matching startup/job/receipt dispatch, numerical validation,
physical recovery qualification, and actual Qwen benchmarks.

CPU-only numerical sample of actual layer3 weights and pinned layer2 input:
the original GGUF was authenticated, the reference activation was
reconstructed, and three 32-row bands each from Q/G, K and V were converted
from original Q8 to BFP8 using the existing codec. An ideal CPU dot product
of the decoded tiles with BF16-rounded activation was compared with the
original Q8 reference projection. Across these nine bands, sampled weight
relative L2 was 0.00721..0.00763 and output relative L2 was 0.00527..0.02930
(cosine 0.999576..0.999986). Two runs gave the same printed results.
These are just 288 rows from one layer and one input; the same codec packs
and unpacks the sample, and the CPU dot does not simulate the P100A matrix
unit. They do not qualify model quality, converted-cache lifetime, full
coverage, hardware arithmetic or speed.

Prepared-page routing, still offline: a separate one-shot derived page source
binds an already verified QGW8 parent and its exact same authenticated model,
packed plan, canonical plan, digest and prepared all-BFP8 source. It uses
the proposed dense Q8 layout to route Q/G, K and V stripes to existing BFP8
cache reads, and delegates other weights to the existing parent. It stages
reads before publication and permanently fails on source/cache changes or a
failed read. A synthetic full-layout test covered all 336 converted stripes,
parent FFN/head/original routes, incorrect identities, aliased output,
two-page failure atomicity and source/plan revocation. The pre-existing QGW8
parent preparation regression also passed. No real dense cache has been
prepared by this test; this is not a driver, upload, inference or speed.

Separate 32-row matrix job geometry: the existing original-Q8 scheduler
uses 16-row groups and cannot simply be reinterpreted as BFP8. A distinct
offline planner now divides the 336 converted Q/G, K and V stripes into
2928 BFP8 worker jobs, with all 229376 output rows covered exactly once
across the 16 dense layers. It schedules 119 workers for each Q/G projection
and 32 for each K or V projection, with 1..8 bands/job, exact bank and
converted-stripe offsets, bounds and output alias refusal. Tests covered
all layers/roles, sequence and context bounds, source and row coverage.
This is not a ROOT scheduler, runnable worker capsule, native owner or
performance result. In particular, K/V currently use only 32 workers; more
parallelism would require safe K-dimension splitting and reduction.
