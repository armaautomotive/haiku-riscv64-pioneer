Purpose and boundary
--------------------
The preceding worker-admission first-layer profile attributed 138,561,868
of 197,243,744 ROOT instructions to Transfer, packet_seal, and Quiet. This
motivates replacing repeated remote worker-proof reads with bounded messages
published by the workers themselves. It does NOT predict physical savings.

This checkpoint implements ONLY the sender. A distinct QGW3 boot/job grammar
prevents the new writes from entering existing QGW1/QGW2 ROOT/native flows.
The unchanged QGW2 full BUILD artifact pins are checked first. Only the new
frontend is compiled; the precise and mathematical object inputs are reused.
Relocated capsule binary hashes therefore differ without changing the math
source. No numerical validation is inserted in production Work mode.

After an actual ordinary matrix operation and its existing completion seals,
the actual RISC worker constructs 256 bytes in local L1: job binding, worker,
layer/position/nonce, all physical source words, and all pre-push counters.
It sends a non-inline, non-posted payload write to that worker's ROOT slot,
waits for command acceptance AND the complete expected outgoing-counter
delta including the write ACK, then sends a separate 4-byte commit write.
CMD_CTRL readback precedes counter observation. An idle command register
alone is deliberately insufficient. Both packets retain source/boot seals,
command readback, finite polling, and exact modulo-32-bit counter deltas.
Unknown completion parks: no retry, counter rebase, reset, or cleanup.

Before each packet the current job/doorbell is still fully sealed. After
the commit becomes visible, only immutable boot/source and outgoing-counter
checks remain, so an arriving next descriptor cannot invalidate the previous
job's return. This does NOT yet qualify execution of that next job.

Primary register/ordering references used in designing this prototype:
https://raw.githubusercontent.com/tenstorrent/tt-isa-documentation/main/BlackholeA0/NoC/Counters.md
https://raw.githubusercontent.com/tenstorrent/tt-isa-documentation/main/BlackholeA0/NoC/README.md
https://raw.githubusercontent.com/tenstorrent/tt-metal/main/tt_metal/hw/inc/internal/tt-1xx/blackhole/noc/noc_parameters.h
https://raw.githubusercontent.com/tenstorrent/tt-metal/main/tech_reports/Blackhole/BlackholeBringUpProgrammingGuide.md

Incoming writes affect ROOT slave counters, not its outgoing master counters.
The modeled ROOT slave delta is starts=2, flits=5, received=2, ACKs=2;
worker outgoing delta is {0,0,2,0,2,5,2,2}, including the aliased accepted
command counter. These are checked against synthetic raw NoC endpoints;
their physical implementation and ROOT cache policy still require validation.
