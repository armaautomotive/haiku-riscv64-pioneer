Scope and exact subject
-----------------------
New PioneerDramReadSweep.h and blackhole_dram_read_sweep.cpp implement a
separate finite READ-only device loop, not selected by any driver/Work
mode. It sweeps a fixed8MiB GDDR window beginning at0x04000000 into the
same private16KiB L1 buffer. Supported transaction sizes64/1024/4096/16384
bytes,1..256 sweeps. No GDDR writes, dequantization, matrix arithmetic,
CPU expected products, host-memory target, PCIe transfer or host polling
inside the loop. The loop has ONE outstanding read on fixed logical
worker(1,2)/NoC0; its command return-coordinate is fixed to1|(2<<6).
It is deliberately NOT a whole-card saturation test or an integrity test.

The exact emitted image has:
 boot4B SHA d0565e4ef0f59aa08ad0be91ffae61ceb85aedff5f36f346c95312b0f9407ac6
 text1252B SHA cde3b6a902dda99343ef0c68a089ad971773ea1d7810fc317fd1e56f5a45a1c2
 ELF10192B SHA7002ccac8cdaf7b4c0cef7890ebc538d666eedbf4b1f407b59ea5e7136cdda5f
The linker rejects writable globals/GOT, bad boot size and any text that
could overlap the complete8KiB stack. Emitted stack frames are240B main
and16B sampler, not a combined native-kernel-stack qualification.

Timing and uncertainty behavior
-------------------------------
The loop samples64-bit mcycle with bounded high/low/high reads before
actual READ issue and after every response is fully complete. The build
audits ALL3 emitted CSR encodings: CSRRS/read-only, rs1=x0, addresses only
0xb80/0xb00. No timer reset, inhibition or CSR writes. Low-counter rollover
and a high/low sampling retry are covered. Timer sampling uncertainty,
zero/backward elapsed time, bad idle state, command readback, busy value,
excess/missing response, stuck outstanding or changed input frame prevents
a successful report. No next request is sent after transfer uncertainty.
Only the local fault marker is written before an inert fault park. It is
DATA, never STOP/HOLD/restore authority. No permissive cleanup is added.

Setup/configuration,upload,final integrity checking and cleanup are outside
the device cycle window. The reported cycles INCLUDE issue/readback,
doorbell,wait and fences, not pure GDDR bus utilization. First/last payload
samples are recorded, NOT a full-span integrity checksum. Frequency must
be independently established before converting cycles to seconds. Per-core
rates must NOT be added and described as measured whole-card bandwidth.

Actual independent instruction tests
-------------------------------------
Main59389 and independent clean20657 BOTH actually exited0, complete logs
byte-identical; whole emitted ELFs also byte-identical. Each ASan/UBSan
execution starts a fresh actual RV32 processor at the real boot instruction
and executes the emitted program through its own success or fault park.
No supplied PC/register/result or host timing is used to manufacture a
device receipt. Synthetic clocks/NoC timing are test stimuli, NOT physical
cycles, memory bandwidth or native ownership evidence.

Each executes6 valid histories, all4 transaction sizes with complete8MiB
address sequences, a repeated sweep and high/low timer retry. Read-response
counter rollover is tested.38 rejected histories cover all16 frame words,
invalid count/shift/route bounds, dirty output, idle/config/source/response/
busy/outstanding failures, changed frame and unstable/frozen/backward
clocks. Invalid-frame/dirty-output cases have ZERO NIU/CSR accesses; no
GDDR WRITE, engine instruction or unbounded wait is permitted by the test.
The plan's256-sweep/2GiB byte-count boundary is checked without pretending
to execute that largest case. Exact actual code is unchanged between runs.
