Experimental matrix-engine dense attention scores
=================================================
November 7, 2026. NOT installed, hardware-tested, a full decoder, or a speed
result. Current Work and validation modes are unchanged.

The existing dense worker computes QK and PV with the card SFPU; it does not
compute them using ordinary CPU fallback, but neither multiplication uses the
matrix engine. The separate BF16 experiment issues actual MVMUL instruction
words for a 32-key by 256-element query score batch. Its staging code reads
the existing private-query FP32 and token-major FP16 key-chunk layouts and
converts them to BF16. Padded keys are zeroed. All four fidelity phases are
issued and eight K32 tiles accumulate in Dst before score publication.
It now also implements a separate one-chunk, 32-output-dimension PV product
using the same matrix engine: the stage transposes token-major FP16 values
and uses the existing normalized FP16-rounded probabilities. The worker
splits each FP16 operand into two BF16 parts and sums all four matrix
products. This gains precision over one BF16 product but needs four times as
many PV matrix operations, before packing/setup costs. Cross-chunk PV merge
and softmax use the existing worker code; recurrent attention and native
integration are NOT implemented here. The staging conversion uses card scalar work;
its speed and any alternative packing or reuse are unmeasured.

The offline ISA observer exercised 1, 17 and 32 keys, 128 matrix commands per
batch, with independent dot-product comparisons, zero-padded keys, invalid
geometry, a failed staging callback, and nonfinite FP16 input. Using the
actual FP16-to-BF16 stage, synthetic relative L2 score errors were 0.000209,
0.000318 and 0.000318 respectively. These are only artificial fixtures:
they do not establish real-model accuracy, token quality or equivalence to
the existing compensated FP16 path. The observer is a software model, not
proof that the BF16 unpack configuration works on physical Blackhole silicon.

The initial ONE-PRODUCT PV variant passed the software instruction observer for sequence
chunks of 1, 17 and 32 and dimension blocks 0, 3 and 7. It issued 16 matrix
commands per chunk/block; the synthetic relative L2 error versus original
FP16 inputs ranged from 0.00103 to 0.00288. These are not the final worker's
four-product results. A host check verified that all 63488 finite FP16 values
reconstruct exactly as high BF16 plus low BF16.

Reproduce with:
  sh tools/pioneer/tests/run_pioneer_q38_dense_bf16_matrix_tests.sh

The experimental QK and PV methods are now wired into the existing QDW1
three-phase partition source behind an opt-in standalone-only build, with
a separate QDM2 header/boot identity. Both products compile into an isolated
RV32 image; softmax and the existing high/low cross-chunk merge remain in the
worker. The ordinary QDW1 image still rebuilds byte-for-byte unchanged, and
its existing role/build guards passed. The individual math/staging observers
above do NOT execute the new complete QDM2 phase protocol. The QDM2 code.bin
SHA-256 was b690682466747bef944e77c3c2c4540207f5a47f5ccbed869fad7c0a33d2a313
before the later query-reuse optimization below. To reproduce the current
image in a new output directory:
  python3 tools/pioneer/build_qwen38_dense_matrix_image.py ABSOLUTE_SDK ABSOLUTE_OUTPUT

An instruction-level observer executes the actual QDM2 RV32 image through
phases 1, 2, 3 and STOP for six heads, using simulated NoC, scalar and matrix
units. A synthetic 33-token local partition exercises two K/V chunks; its
score relative L2 error versus FP16 reference was 0.000463 and its PV error
versus FP16 values and the worker's own probabilities was zero in that
fixture. Local partitions of lengths 1, 2 and 3 also passed. Test-only control
then reduced all 24 workers for synthetic sequences of 1, 33 and 65 tokens.
Relative L2 of merged output versus the existing QDA reference was 0, 0.00109
and 0.00169 respectively. The four-product PV replaced an earlier one-product
attempt that failed the 0.01 threshold at 65 tokens (relative L2 0.01226;
isolated PV contribution 0.01204). That fix has not been shown to improve
speed, and the extra products may make it slower. The global controller and
NoC are synthetic: these are not real model data, silicon execution, model
quality, or a speed measurement. One first
compile emitted an unsupported byte store; the flag is now word-sized and the
builder explicitly rejects byte stores. Run the observer with:
  python3 tools/pioneer/tests/run_pioneer_q38_dense_matrix_worker_tests.py ABSOLUTE_QDM2_DIR ABSOLUTE_QDA_DIR

Reuse experiment: the original correct four-product worker reconfigured and
cleared Dst separately for every product and converted its inputs four times.
The new worker retains Dst across four products and creates both BF16 operand
components only once in private L1, switching operand addresses between
products. On the identical simulated 65-token/24-partition fixture, the
observed worker RV32 instruction total fell from 122345677 to 49074401
(about 59.9% fewer); matrix operations remained 84480 and merged output
relative L2 versus the existing QDA reference changed from 0.00168826612 to
0.00168827224. At 33 tokens, steps fell from 88470424 to 36059261 and the
matrix operation count remained 65280. These are instruction-model counts,
not cycles, PCIe traffic, physical latency or token throughput. They cannot
establish a real speedup. New L1 reservations and reordered accumulation are
unqualified on silicon and in the mixed worker. Fault tests include rejected
staging order and no successful publication after an interrupted part.

Query-reuse optimization: QK staging formerly read and converted each FP32
query component eight times, once for each repeated vector row. It now reads
and converts each component once per tile, and copies the resulting bits to
all eight rows. The input remains on-card and no numerical reference or CPU
fallback is involved. On the same 65-token/24-partition synthetic fixture,
RV32 worker steps fell from 49074401 to 45375233 (about 7.5%); at 33 tokens
they fell from 36059261 to 33200813 (about 7.9%). Both versions issued 84480
and 65280 matrix operations respectively, and the printed merged relative
L2 errors were unchanged at 0.00168827224 and 0.00109330609. These counts
are a software instruction model, NOT physical timing or tokens/sec. The
tests verify the vector rows' bit patterns, bounded query read counts and
nonfinite-query refusal. On the same 1-, 33- and 65-token synthetic inputs,
one actual-instruction worker per case produced bit-identical scores,
probabilities and partial outputs versus the previous QDM2 image. Two
independently built QDM2 code images match
(SHA-256 5708c68c3acb456789a90523cbecf2214c20bdd16ed7a5d5fb0113b3613c37ae),
and two QGW7 linked images also match. The QGW7 mixed-worker and direct ROOT
job handoff simulations passed with the new code; they remain offline tests.

A separately identified experimental hybrid mixed-worker link and transition
simulation are described in qwen38-hybrid-matrix-attention-20261107.txt.
No native/full-model integration, complete L1 coexistence proof, physical
ownership, timeout recovery, silicon correctness or measurement is
established. Do not substitute this experimental worker into production yet.
