Qwen 27B: fewer on-card recipe transport commands
================================================

The prior measured v3 profile includes 10,989,310,829 controller cycles
(4.54% of the decode body) in all metadata work. In that path a layer
metadata recipe is 5,120 bytes. The controller fetches every recipe
separately, runs the original token/layer/slot checks and transformations,
then copies it locally or publishes it to its original GDDR slot.

The isolated v4 inspection arm groups adjacent recipes without changing
bytes, destinations or per-recipe operations. It uses at most 15,360
bytes in the existing 16-KiB scratch transfer window. It verifies every
recipe in the group before publishing the group, and leaves the original
Transfer/Scope authority, per-packet readback and counter checks intact.
It neither prefetches across layers nor exposes a new route or map.

  recurrent (48 layers): eight GDDR recipes, 16 -> 6 requests
  dense (16 layers): four local plus three GDDR recipes, 10 -> 4 requests
  total per decode position: 928 -> 352, 576 fewer requests

These are recipe requests only, not all NoC traffic or PCIe transfers.
There is no timing evidence yet. Even magically eliminating the entire
historic metadata bucket would save only its measured 4.54% of body
cycles in that workload; the candidate removes only a subset of it.

  python3 tools/pioneer/build_qwen38_recipe_batch_root.py SDK PINNED_V4_ROOT NEW_OUTPUT
  c++ -std=c++17 -O2 -g -Wall -Wextra -Werror -ffp-contract=off \
    -fsanitize=address,undefined tools/pioneer/tests/pioneer_q38_token_recipe_batch_test.cpp \
    -o /tmp/q38-token-recipe-batch-test
  UBSAN_OPTIONS=halt_on_error=1 /tmp/q38-token-recipe-batch-test

The builder splices only TokenRecipes into the frozen v4 source, not
the newer workspace's GDN redistribution code. With the role disabled,
it reproduces the original token object and complete v4 ELF byte-for-byte.
The new link keeps its boot, STOP, and timing image unchanged and uses
exactly the original other ROOT objects and workers. Three alternate role
combinations refuse at compile time. Two candidate builds of the pinned
source reproduced identical ELF bytes. The candidate sender's stack is
64 bytes; text 130,908/131,072 and conv 32,512/32,768.
ELF SHA256 ee6e0765744b935bc299e597e1b10859aa944e9114b9bbed915e135cb299be29.

The mock transport test compares every transformed word with the original
per-recipe calculation, using canonical packages for all 64 layers,
seven banks, and three token positions. It checks immutable input bytes,
the exact destinations, the total packet count, and that rejected or
failed reads/recipes do not publish their group. It is not an execution
test of the linked ROOT.

Linked RV32 transport fixture
-----------------------------
  python3 tools/pioneer/tests/run_pioneer_q38_recipe_batch_instruction_tests.py \
    SDK PINNED_V4_ROOT PINNED_RECIPE_BATCH_ROOT

The test pins both complete ELFs and extracts their actual code and entry
symbols. It builds the canonical fixture from the same frozen vector92
tree as v4, rather than mixing it with the newer GDN cohort geometry. It
executes both linked TokenRecipes bodies and the real Owner, Scope,
Transfer and recipe checks. Only the predecessor and NoC completion are
synthetic. It compares complete published byte arrays and byte counters,
checks the ordered ten-word readbacks on each side of every command,
and confirms an unacknowledged request reaches the real fault path after
the bounded poll. An input error at any slot may leave earlier complete
groups published, but never the failed group or any group after it.

The ASan/UBSan run passed 200 matched cases and 90 injected refusals.
All 64 layers were tested at position 31 on bank 0; both ends of both
layer families were tested at positions 0, 31 and 8191 on all seven banks.
Actual emitted commands for the complete 64-layer pass were 928 -> 352.
Across the 200 cases, retired emulated RV32 instructions were
251,347,460 -> 211,932,324; nested stack depth was 1024 -> 1040 bytes.
Swapping the two ELF inputs was refused before execution.

This is still offline evidence: it does not test physical timing, matrix
throughput, or whole-model execution. The running tag213 profiler uses the
original sender. A separate guarded native A/B remains necessary.
