Raw-Q4 shared FFN input: repaired ROOT admission (offline)
=========================================================

The earlier raw gate/up input-reuse candidate checked the previous
frame's word 53 for a nonzero input address. Its caller actually passed
the sealed raw recipe from RecipeCopies. The raw FFN recipe requires
words 46–63 to be zero, so the check rejects the valid gate->up path
before the second projection. The old fixture set word 53 on both
frames, which did not model this distinction. This is separate from
the November 13 BF16 producer-reuse experiment.

The new inspection profile compares the authenticated gate recipe
with the current private up frame. It requires the same request
position, source token, layer, banks and source identities, adjacent
recipe sequence, exact 5120/Q4 gate and up roles, and the fixed
normalized input alias supplied from the materialized frame. The
existing caller seals the recipes and runs these two projections in
immediate sequence. This fixes admission only; the existing worker
and ROOT audits, weight tiles, result math and receipt accounting are
unchanged. The preexisting mode can skip two worker input reads (10,368
bytes) per active role-3 worker. The 48 recurrent layers' theoretical
source count is up to 11,424 reads / 59,222,016 bytes per token. That is
on-card activation traffic, not PCIe or a physical timing estimate.

The real-format predicate passed ASan/UBSan and the candidate pairing
checks. The compact RV32 ROOT built twice, byte-for-byte, for inspection.
.text is 120,656 of 131,072 bytes and .conv 29,504 of 32,768 bytes;
boot and terminal keep their established bytes. The emitted EOG test
passed. Complete ELF SHA256:
e59cdec3d494e7a264b6904fc6cca62fae49fb82d593ef070c5ff52b383b979d.
The default and historical pinned build profiles were not repointed.

Linked controller test
----------------------
The ASan/UBSan harness loads the actual .text/.conv from the exact
pinned ELF. It builds the two real schema-valid recipes, executes the
linked Matrix() materialization, copy, Shape and inlined admission,
and observes the call to Projection::Run. The outer seals, phase
publisher and projection arithmetic are explicit fixture endpoints.
Each layer uses the same 5,120 actual input words for gate and up.
The same image's real job writer emitted both 119-worker streams with
the expected per-worker identity, weight coordinates and nonce: gate
fetch=1, up fetch=0. Thirty-two late mutations of either the gate
recipe or current up frame faulted before a second projection call.

Linked worker retention comparison
----------------------------------
The existing raw reuse worker was rebuilt as an inspection-only
QGW3 ELF (SHA256
25c286eb0bce198e8c8207c4097eca5f54cce91411dc9ec7f0a484685a72549c).
The ASan/UBSan emulator ran actual worker, matrix and pushed
receipt code with synthetic raw Q4 weights, matched gate/up inputs
and different gate/up weights. Each worker kept its guest state
between jobs. All 10,240 operand bytes and 128 padded scale bytes
survived gate completion and were unchanged after the up job.

Workers 1/60/119 returned 160/144/144 bit-identical up rows against
their forced-refetch controls and passed separate FP32/FP64 row checks.
They executed the same tensor instruction counts and actual payload/
ACK/commit sequence. Read commands were 200/180/180 with retention
versus 202/182/182 with refresh, exactly 162 fewer NoC flits per peer.
Invalid retained representations (operand or scale) faulted before
any new NoC read, tensor instruction or receipt. This does not claim
detection of arbitrary valid bit substitutions in retained memory.

Measured vector92 sender port (offline)
---------------------------------------
The fresh build reproduced the complete worker used by the measured
vector92 release (ELF SHA256
4b3dc0c96d3888b9c43af683f58678cc91cade7c67e955413bad8c5e16d52870)
and matched all ten peer arrays in the shipped native program header.
The port changes only .globalworker (9,232 to 9,500 bytes). The other
nine sections, including vector-Q4 metadata and Tensix math, are
byte-identical; the flag-off sender object also matches exactly.
Two fresh builds reproduced the candidate ELF SHA256:
aefeb0c7cad0eeb1f13867b2c77e473dca4eeb482ad7c9a97cd00d29b19a3f43.

The sender only skips an input fetch on an ordinary Q4/K5120 job
when the previous local job filled the retained operands, completed
its real push receipt, and has matching layer/position and the
immediately preceding recipe number. ROOT still owns the actual
gate/up pairing and input identity. Five compile-role refusals and
the original read-only CSR audit passed. No native image was built.

The ASan/UBSan emulator ran real vector92 matrix and sender bytes on
workers 1, 69 and 119 with synthetic Q4 weights. The baseline, new
sender with refetch, and new sender with retention all agreed on the
same 448 up-projection rows and full Tensix instruction stream. The
emulator observed 102->100, 92->90 and 92->90 reads respectively,
exactly 162 fewer 64-byte activation flits per worker. Both jobs used
actual payload/ACK/commit receipts; the 10,240 operand and 128 scale
bytes stayed intact. Seven off-contract jobs (old sender, cold skip,
wrong recipe/layer/position, invalid operand/scale) stopped before new
NoC reads, tensor work or a receipt. These are not measured clocks or
tokens/sec. They do not replace the exact vector92 ROOT pair and native
guarded A/B run required to establish a benefit.
