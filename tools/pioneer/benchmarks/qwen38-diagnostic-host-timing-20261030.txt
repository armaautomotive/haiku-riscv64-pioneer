Optional host timing for the full-token USER diagnostic
======================================================
2026-10-30. Goal ACTIVE;last physical whole-model0.207893161tok/s;20 UNMET.
This checkpoint adds measurement capability,NOT a measured speedup.

The existing three-position,cancellation and source-only frontend accepts
an optional FINAL --host-timing argument. Without it no additional clock
reads or timing output occur. With it,stderr reports HOST wall microseconds
in upload/start/observe/cleanup/other ioctl buckets,with counts,total,max.
The five available wall intervals are source-to-device-open,device-open-to-
Start-return,Start-return-to-terminal-observation,terminal-to-clean-close
and total diagnostic. Failed/incomplete sessions omit absent milestones.
Hold/Read/Finish are cleanup;Cancel is Other,not a cleanup/completion grant.

These intervals include host scheduling,packing,transport and polling where
applicable. They are NOT device clocks,kernel cycles,pure packing time or
sustained decode throughput. Three processed positions include TWO prompt
positions;dividing three by a wall interval is NOT decode tokens/sec.
There is deliberately no automatic rate calculation. Timing DATA never
permits Start,Cancel,END,retry,recovery or Work. The existing source,packet,
reply,ownership and close-only policies remain unchanged.

Clock regressions,negative times,duplicate milestones or invalid indices
permanently invalidate timing. The report then emits ONLY valid0,not partial
plausible durations. This telemetry failure does not introduce a new device
command or alter the session's error/recovery policy. Preserve stdout and
stderr separately when collecting a future trial:the strict posthoc record
comparator remains UNCHANGED and does not accept timing lines as records.
