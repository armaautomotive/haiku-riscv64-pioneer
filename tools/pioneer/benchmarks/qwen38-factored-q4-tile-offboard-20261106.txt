Why this code exists
---------------------

The proposed algorithm computes dot products of original unsigned Q4
codes using native BFP8, then corrects outputs with original scale/minimum
metadata and the input sum. This is a DIFFERENT operation order from old
per-weight BF16 rounding. Full-model quality is not established.

The arithmetic prerequisite was checkpointed separately. This component
connects original packed bytes through vector extraction, integer PACK,
temporary L1 tile and native matrix instructions to real dot/input-sum
results in the strict SOFTWARE instruction model. It does NOT yet connect
original metadata and final affine correction or accumulate the full K.

Implemented
-------------

PioneerQ38Q4FactoredTile.h and blackhole_q38_q4_factored_tile.cpp produce
BUILD-only functions, not a native owner/returning worker/Work selection.
Original byte-major panels remain at L1 0x90000 and input at 0x96000.
New temporary native-code/ones tiles at 0x88000/0x88800 require a new
explicit memory-ownership journal before native use.

Raw UINT8 UNPACK populates physical Dst without dummy source publication.
Two SFPU bit operations extract q*8; INT8 store and PACK preserve those
magnitude bytes. Exponent 130 represents q exactly for q in 0..15.
Only computational constants/headers are scalar-written. No scalar
learned-weight/input reads or host-supplied dot/input-sum are permitted.

PACK uses 16 four-row groups, Last on the final group, never Flush.
The explicit 0xa210181e wait includes PACK, unlike generic 0xa2101816.
Global destination-format override is explicitly INT8 during PACK and
restored to FP32 for matrices. Shared PACK/UNPACK config words are restored.
The existing input-major layout requires no within-face transpose here.

Each group executes a genuine ones-tile matrix, reads its completed sum
from on-card destination MMIO, then executes the packed-code matrix.
The latter leaves qdot in Dst rows 32/40. Both source banks retain their
real publication/consumption history across all eight groups.

Two fidelity phases are used ONLY because q<=15/ones have at most four
significant bits; arbitrary BFP8 weights are not granted this shortcut.
The same packed tiles/inputs also pass a separate four-phase control.
This instruction-model evidence is not a physical hardware guarantee.

Audit correction / limits
--------------------------

Earlier main-final/clean-final suites exited 0 but were superseded:
the first model omitted the global destination-format override, which
would override local integer PACK format. Code now selects the integer
override explicitly; the model decodes it independently and a new negative
case rejects the old setting. No hardware ran this code.

Earlier corrected logs had complete PASS output, but their original
runner handles were not retained across context; actual exits are not
asserted from those logs. A process-list check confirmed those runners
absent before the final main/clean suites above were launched and their
actual exit results retained. No quiet/live job was blindly restarted.

The fixture reuses the existing physical Dst/UNPACK/FPU observer, adding
only the new integer PACK subset. It is not a new whole-card emulator.
Software models can miss hardware behavior; native tests remain required.
No equality to the old BF16/GGML operation order, full-model quality,
hardware utilization, attainable speed or 20 tokens/sec is claimed.
