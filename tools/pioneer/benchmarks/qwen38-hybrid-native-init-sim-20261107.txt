Hybrid 27B native initialization: simulated endpoints
=====================================================
November 7, 2026. No Pioneer/card, real model weights, full inference,
numerical-quality result or speed measurement was used or established.

The integration regression constructs the real 22,005-extent sealed hybrid
receipt with synthetic page/hash ledgers; runs the actual native binding;
then executes the production recurrent, convolution-history and projection
initializers with the real pinned zero-program RV32 instructions against
simulated OS, MMIO and DRAM. The simulator is populated with addresses from
the relocated hybrid layout, not the original Q4 layout.

PASS: all 672 recurrent regions (73,728 pages), 336 history regions (1,680
pages), and selected projection workspace (512 pages) initialized and
closed. The simulated learned-page ledger remained unchanged; no bank was
quarantined. A second initialization attempt was refused with no additional
simulated I/O. A separate original-layout native initialization regression
also passed. These are not hardware startup, KV initialization, model
execution, a quality comparison, or proof that a real device can recover.

The same sealed receipt and initialized owner also passed the real held-memory
preparation and restoration code against simulated hardware/VM endpoints.
The test covered all 120 workers, 119 newly prepared store leases, four
simulated aliases, and the converted address manifest. It saved and restored
34,453,122 words and installed 3,452,256 program words, leaving workers held
and the learned-page ledger unchanged. No worker was launched. This is not a
physical execution, a full token, or proof of real hardware cleanup.

Direct held-memory regression with the pinned input artifacts:
  python3 tools/pioneer/tests/run_pioneer_q38_token_native_initialization_tests.py ABSOLUTE_ZERO_IMAGE --held --hybrid-qgw5-header ABSOLUTE_QGW5_HEADER

The next runtime-staging regression also passed for both the hybrid and the
original layout. Following initialization and held-memory preparation, the
actual native runtime factory staged and read back 37,782,528 bytes of startup
metadata, prompt, position data and empty output areas using 4,616 simulated
transfers, checked all 120 worker boot-data records and restored the held
memory journal. The expected bytes were built independently from the same
canonical startup-plan implementation; this is not an independent model or
numerical oracle. No worker was started and no model weights or tokens were
computed. The unchanged original path passed the same runtime check.

Direct runtime regression with the same pinned input artifacts:
  python3 tools/pioneer/tests/run_pioneer_q38_token_native_initialization_tests.py ABSOLUTE_ZERO_IMAGE --runtime --hybrid-qgw5-header ABSOLUTE_QGW5_HEADER

The native worker-bootstrap stage also passed in simulation, starting from
the same hybrid receipt, initialization and runtime-staging history. All
119 simulated workers executed the actual pinned QGW5 boot instructions
and reached their idle wait; the root remained held. The test observed
14,896,896 worker instructions and no matrix or model computation. The
original-layout bootstrap regression also passed. This verifies simulated
worker boot only, not root launch, model output, physical cleanup or speed.
