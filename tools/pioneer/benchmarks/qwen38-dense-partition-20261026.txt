Purpose and implemented path
-----------------------------
A serial six-head batch would reuse KV but leave too few compute workers.
NEW QDW1 instead divides each of four KV groups over24 sequence partitions:
96 worker bindings,each calculating six queries against its OWN prefix slice.
Each K/V chunk is fetched ONCE and reused across those six heads. Current
token K/V is overlaid from provisional input,never read stale from the cache.
Only prior canonical-prefix positions are read. NO canonical KV write,
token/state commit,host-output endpoint or CPU numerical fallback exists.

The ACTUAL emitted worker implements a persistent THREE-phase protocol:
1. Capture six prepared queries/current KV into private scratch. Compute
   local QK scores and six local maxima,using token-parallel32-lane SFPU.
2. After a separate controller supplies the six GLOBAL maxima,compute
   exponentials and exact software-binary64 LOCAL denominator records.
3. After the controller supplies the six GLOBAL inverses,round probabilities
   to F16,read V once per chunk,and retain six256-wide compensated high/low
   partial PV vectors for controller merging/gating.
An actual private sequence enforces1->2->3->STOP. Duplicate waiting requests
are inert;skips/stale jobs fail. STOP is accepted only after phase3. Failed
or partial phases do not invent cleanup permission or successful completion.
A future native owner still owes quarantine/holds/restoration on failure.

Every prefix packet seals the immutable frame,all16 source words,the job,
and (for PV) global parameters,before AND after the packet. Counter models
include wraparound and the real shared counter2/6 register alias. Wrong
commands/counters/source/frame/job/parameters/timeouts cannot issue a later
packet or publish a successful private completion. These are structural
checks,not CPU numeric validation. The no-CPU-reference Work path remains
distinct from offline CPU observers and the existing separate DEBUG client.

--------------------------------

control overhead;this is not a blanket latency gain or6x speedup claim.
