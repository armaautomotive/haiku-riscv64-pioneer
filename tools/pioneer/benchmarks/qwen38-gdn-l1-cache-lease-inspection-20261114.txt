Qwen3.8 recurrent L1-cache lease metadata experiment — 2026-11-14

Purpose
-------
The scattered-state worker experiment needs more than a page table: each L1
entry must be invalid until initialized, must not be reused after a partial
token, and must become current only after every GDN layer and the global
GDDR-state slot flip complete. This isolated metadata class wraps the
existing GDN state transaction and models those transitions for the 119-peer
candidate map.

Behavior
--------
* Maps each logical half-state through the existing layer-dependent 119-peer
  route. Per-worker state indices 0..33 are marked cache-resident; higher
  indices are explicit GDDR spills. The corresponding static capacity test
  validates 34 fragmented 32 KiB slots on each physical peer.
* Bind starts cold. A resident cache entry is a hit only when its page data
  was published by an earlier complete token and its identity, position, and
  GDDR slot match. The cold token must populate resident pages from the
  authoritative GDDR state.
* Completion of a resident half invalidates its old cache entry immediately,
  preventing reuse of partially updated state during the same token.
* Cache entries become valid for the new GDDR slot only after all 48 layers,
  all 96 logical halves per layer, and the state owner's slot flip succeed.
  A fault invalidates the entire L1 cache; recovery must refill from the
  still-authoritative old GDDR slot.
* A caller-supplied `l1WritebackProved` receipt is metadata only. This class
  verifies sequencing and the resident-versus-spill expectation; it cannot
  verify that hardware really wrote the pages.

Validation
----------
Reproduce with:

  `tools/pioneer/tests/run_pioneer_q38_gdn_l1_cache_lease_tests.sh`
  `bash tools/pioneer/tests/run_pioneer_q38_gdn_l1_cache_plan_inspection_test.sh`

The ASan/UBSan lease test covers a cold token followed by three warm tokens,
all 4,608 half-states, 4,046 resident entries, 562 deterministic spills,
48-layer/96-task commit ordering, inconsistent receipts, stale cache reads
during an incomplete token, and full invalidation after a mid-token fault.
The compile-role test accepts inspection mode and rejects Work, CPU-reference,
native, resident-image, and kernel roles. The existing placement test checks
all fragmented pages against the captured 119-peer L1 snapshot and confirms
the same 4,046/562 split.

Limits / next gate
------------------
This is deliberately inspection-only and has no caller in native inference.
It does not allocate or initialize pages, copy GDDR state into L1, program a
per-worker page table, prove native worker completion, or benchmark tokens.
The next required implementation is an address-indirect state transfer and
page-table submission in the native GDN dispatch, with a safe cold-fill path,
explicit 562-state GDDR fallback, cache invalidation on all fault/reset paths,
and CPU-reference-independent runtime receipts. Only then can hardware tests
measure whether the saved GDN state reads improve full-token throughput.
