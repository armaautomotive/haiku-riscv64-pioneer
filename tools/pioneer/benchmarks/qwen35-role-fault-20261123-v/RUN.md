# Resident role fixed-fault qualification, stage v

After a fresh idle-driver, process, lock and staged-file preflight, both full model hashes matched. The one-shot wrapper repeated the hashes and loaded restricted tag `2026112300030013` on driver60 generation 9. The fixed qualification inspected and retained the images of all 120 held workers, then started only worker zero’s B/NC resident roles with TRISCs held.

The controller saved the selected invocation word and all queue-control words, deliberately set an invalid buffer address, and required both actual resident roles to report failure for command 1 with the expected queue-failure values. It sampled NoC quiet, requested a fault stop, observed both stop and local-restore receipts and parked PCs, held B/NC, restored the original invocation, queue words, mailbox, handoff and reset-preservation setting, and restored and audited the original fleet images. The client reported `stage=12 captured=1 staged=1 restored=1 mappings_closed=1` and a clean bank-session end.

The wrapper then hot-reloaded stable55 without reboot and returned `ROLE_SERVICE_FAULT_PASSED_STABLE_RESTORED`. An independent postflight observed stable driver55 generation 10 idle (`cold0 active_owner0`), expected stable-driver and guard hashes, no diagnostic process or exclusive lock, and expected model metadata.
