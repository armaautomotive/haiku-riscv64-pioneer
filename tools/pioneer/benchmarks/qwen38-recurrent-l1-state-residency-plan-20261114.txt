Qwen3.8 recurrent L1 state-residency feasibility plan, November 14, 2026
=======================================================================

This is a static placement experiment, not an implementation, device run, or
speed claim. The current qualified full-card path remains tag92 vector-Q4 at
0.172813448..0.172816755 tokens/sec. The independently checked tag99 profile
attributes 59.078% of its aggregate timed cycles to recurrent layers, but
includes control/NoC waits and is not a breakdown of state-copy time.

Correction to the first 119-tile estimates in commits c28b5a5105 and
929e5e320f: those estimates used a hypothetical redistribution across 119
tiles, but the existing GDN state API and descriptor reject workers >= 96.
Those counts must not be treated as current-runtime capacity. The calculations
below first use the actual 96-worker mapping, then separately re-evaluate
redistribution as an explicit alternate-topology experiment.

Geometry derived from the current source:

* `PioneerQ38CanonicalModelPlan` has 48 recurrent transformer layers
  (the 64-layer stack excludes every layer where `layer % 4 == 3`). Each
  recurrent layer has 48 heads. One FP32 head state is 128x128 = 64 KiB;
  the existing GDN worker processes each head as two 32 KiB halves.
* One selected current-state slot for the whole model is therefore
  48 layers x 48 heads x 64 KiB = 144 MiB, or 4,608 half-state buffers.
  A second complete state slot would double that to 288 MiB.
* The local scratch probe documents 1.5 MiB L1 per tile. The current GDN
  state API accepts exactly 96 workers (`PioneerQ38GdnState::Slice` rejects
  worker >= 96 and the resident descriptor routes workers 0..95). A static
  round-robin assignment of `layerOrdinal*96 + halfOrdinal` modulo 96 gives
  each recurrent layer 96 distinct owners and assigns exactly 48 state halves
  to each worker. Those 48 x 32 KiB states consume all 1.5 MiB, leaving no L1
  for executable image, stack, activations, or scratch.

This is a static capacity check, not a fitting cache design. The GDN arithmetic
uses a separate Dst and currently has explicit local addresses for input,
prior and next buffers; persistent state, code/data and other worker phases
have not been jointly relocated. Full residency is impossible in the current
mapping unless other L1 live data is relocated/streamed or worker topology is
redesigned. In-place state updates, token-abort behavior, reset/zeroing,
barriers, all 96-worker ownership, and interaction with matrix/FFN scratch are
not implemented or proven. If these constraints cannot coexist, state must
remain in GDDR; no lossy BF16 state cache is assumed.

Reproducer:

  `sh tools/pioneer/tests/run_pioneer_q38_gdn_l1_cache_plan_inspection_test.sh`

The ASan/UBSan test exhaustively maps all 4,608 state halves, checks
per-layer owner uniqueness, slot alignment/non-overlap, L1 bounds, exact
48-slot occupancy, recurrent-layer ordering, and that no L1 scratch remains
when all state is assigned. The helper has an inspection-only role guard and
has no native/Work selection or device access.

Follow-up capacity bound using the exact current QTP3 pushed-image L1 snapshot
spans and the actual 96-worker GDN API: with 64-byte alignment, only 31
complete 32-KiB state slots per peer tile fit in regions the snapshot never
touches. Across 96 peers that is 2,976 slots / 97,517,568 bytes (93 MiB) of
4,608 halves. The remaining 1,632 slots / 53,477,376 bytes cannot be placed
without relocating or shrinking existing saved L1 footprint. The separate
GDN input-buffer-reuse image frees 32 KiB within its phase, but other phases
may reuse those addresses; it does not close this static deficit. This
conservative free-range check is not a full temporal live-range proof.

A second offline packing check used the GDN worker's existing 4-KiB chunk
granularity instead of requiring each 32-KiB state to occupy one contiguous
range. The same exact snapshot spans leave 274 intact 4-KiB pages per current
GDN peer. Grouping those pages into eight-page state halves yields 34 state
buffers per peer, or 3,264 of 4,608 halves (106,954,752 bytes / 102 MiB),
leaving two unpaired pages per peer. This gains three state buffers per peer
over contiguous placement, but misses the actual 48-state demand by 14 buffers
(1,344 halves / 44,040,192 bytes total). Reaching that demand from the current
packing requires 110 additional 4-KiB pages per peer after using the two
residual pages.

Reproducer remains
`bash tools/pioneer/tests/run_pioneer_q38_gdn_l1_cache_plan_inspection_test.sh`.
The ASan/UBSan test verifies 4-KiB alignment, that every packed page is within
the exact untouched ranges, no page is assigned twice, all 96 worker totals,
and a bijection from the model's 4,608 logical layer/head/half-state entries
to the current per-worker slots. Of these, 3,264 are assigned to the
QTP3-untouched L1 ranges and 1,344 spill to GDDR. This is only a capacity and
static mapping result. The current GDN image consumes contiguous local-buffer
addresses; no scattered-page import table or address-indirect chunk loader
has been implemented, and the 4-KiB packing cannot be used until that path is
built and its cost/live buffers are included in a complete multi-phase L1
map. No model run or performance claim follows from this result.

Separate alternate-topology experiment: retain the 96 logical head-half tasks
per recurrent layer, but rotate their physical owners across all 119 peer IDs
using `physicalWorker = (layerOrdinal*96 + logicalWorker) % 119 + 1`, and the
existing peer coordinate mapping. The route calculation now lives in the
shared pure-metadata helper `PioneerQ38GdnTaskPlacement.h`, including the
inverse route for rejecting inactive peers. The offline test compares all 119
peer coordinates against `PioneerQ38MixedWorkerLayout::Peer`, confirms the
old 96-peer GDN map is unchanged, and proves 96 unique peer routes per layer,
uniqueness across all 119 physical peers, and a bijection of every recurrent
state half. The loads balance at 86 peers with 39 state halves and 33 peers
with 38. Given 34 untouched-range state slots per peer, 4,046 halves could
be resident and 562 would still spill to GDDR. `PioneerQ38GdnState::RedistributedSlice`
now exposes this candidate route alongside the existing logical state slice;
the same-token test exercises all 48 ticketed layers, all 96 logical tasks per
layer, completion, and final slot flip. Existing `Slice()` behavior remains
unchanged. This is still not wired into hardware dispatch: current descriptors
bind each logical task to its fixed peer, and no layer-dependent task launch
or scattered-page import exists. The 119-peer result is a redesign target,
not a capacity or speed claim for current Work.

Reproduce both checks with:

  `bash tools/pioneer/tests/run_pioneer_q38_gdn_l1_cache_plan_inspection_test.sh`

Recommended next engineering gate: build a non-loadable image-layout
prototype that puts the persistent selected state cache and a complete GDN
worker image/scratch footprint together on shared L1, then run multi-token,
all-layer state-transition and fault/abort tests. Do not change the qualified
driver until the existing live image peaks, all-task lifecycle, and numerical
results are covered. Only after that should a separate physical trial measure
recurrent cycles and whole-model tokens/sec. Physical access remains gated on
independent out-of-band verification of the Pioneer SSH host key.
