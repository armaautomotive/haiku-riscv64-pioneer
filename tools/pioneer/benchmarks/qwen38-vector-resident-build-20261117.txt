Qwen 27B: resident requests with unchanged vector92 compute (tag210)
==================================================================

Goal: avoid a second 19,399,024,640-byte raw weight upload when testing
another request. This is separate from output-head batching and does
not target steady decode rate. Nothing was staged on the Pioneer.

The distinct tag210 pairs vector92's four ROOT and ten peer arrays with
the existing resident request lifecycle. It does not change the legacy
tag91 resident or tag92 one-shot selections. Request close still restores
the L1, code, host, PCI and clock scopes. The same FD can then open a fresh
mutable request context while retaining the read-only weight reservation.
Explicit model END still owns final unreserve. CPU vocabulary/text work
is unchanged; there is no host inference, comparison, or fallback.

Guarded native runner and independent transcript inspection
------------------------------------------------------------
The runner binds the exact resident driver, worker and client above and
one independently observed stable generation. It uses the same exclusive
lock as the head and FFN trials and has no one-shot/CPU inference fallback.
It has a no-driver-change preflight and allows one launch; closure requires
the resident client's explicit one-upload/two-request/model-END marker and
zero status. It restores the known-good driver only with verified idle
ownership; uncertain ownership leaves the shared lock and recovery evidence.
The original head and FFN runner bindings remain unchanged.

The independent capture reader checks the complete transcript: exact cold
upload, no upload rows before the warm START, distinct request IDs, both
31-prompt/32-output windows and answers, timing bounds or explicit timing
unavailability, the final model-END marker, exit files, and empty stderr.
It does not give cleanup authority; artifact identity, actual process
closure and stable-driver restoration must still be verified separately.
The fake-manager suite now covers 66 cases across the three runner families.
The sanitizer-checked actual client/fake-peer suite validated measured and
explicitly unavailable synthetic transcripts; ten corrupted transcripts were
refused, including a second upload. Historical one-shot comparators passed.
