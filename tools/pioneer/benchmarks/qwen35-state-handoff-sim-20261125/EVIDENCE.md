# Two-position first-layer simulator state handoff

The two simulator processes used the authenticated Qwen3.5-4B layer-0 fixture, the same position-zero per-core templates and stream records, and the same 120-worker sharded resident service and role images. The first used token 42, position 0, and exported its reference-checked history and recurrent state. The second imported those bytes and sent a position-one command; the test checked that the command changed only position and checksum and that the dynamic patch swapped both state read/write buffers. It checked the second state and layer intermediates against independent references and required both history and recurrent state to change. Both runs completed 21 barriers and intentionally faulted at record 22. Neither published a completion candidate.

In the second process, all 524,288 recurrent-state values and 4,096 gated outputs matched the reference (maximum absolute errors `3.30248383e-7` and `2.20862447e-7`). The 2,560 final layer outputs matched within maximum normalized error `9.4990531e-8`; all 24,576 history entries were checked. Complete outputs are `token0.log` and `token1.log`. The two state buffers are carried across *separate simulator processes*: this does not establish persistent-service execution across tokens, whole-model inference, physical card correctness, warm model output or tokens/sec. The logs' simulation rates are not Pioneer performance measurements.
