Preserve returned native failure stage
--------------------------------------
The diagnostic worker now retains the matched integer START/FINISH failure
reply from the original failing ioctl. Previously it lost that data when
the syscall reported an error and could only say `stage=start` or similar.
START stages identify bind (1), state/history/projection initialization
(2/3/4), held L1 preparation (5), runtime staging (6), worker bootstrap
(7), and ROOT startup (8). The optional inner phase is printed only for
START stages 5-8 and FINISH stages 1-7, where the kernel record actually
has a phase field; zero means none was reported. Malformed or empty replies
do not produce a native stage. The phase is data, not recovery authority.

The diagnostic reads no new ioctl, does not expose any raw addresses or
returned records, and does not change the failure, cancellation, output,
CPU-reference, or cleanup policy. It does not change the active trial's
already-loaded worker or retroactively explain a previous failure.
