Purpose and actual change
-------------------------
The standalone recurrent and dense controllers each owned a host command
loop. A common whole-model device scheduler must call both arithmetic
families and receive control back, keeping the SAME workers, nonces and
GDDR intermediate hidden vector. It must not close/reopen an old native
owner or transfer hidden products through the CPU between layer families.

New q38_return_recurrent_layer() and q38_return_dense_layer() contain the
real existing arithmetic calls, not stubs. They load QLC1 boot/outer DATA,
take their OWN correctly typed private snapshots, bind s11 during arithmetic
and restore the parent's s11 before returning 5120. Minimum parent/local
private ranges must be aligned, in the existing stack window and disjoint.
No recurrent private type is cast into a dense type or native owner.

Recurrent arithmetic includes normalization, eight projections, Conv/GDN,
residual/FFN and final hidden write. It additionally copies the actual Conv
NEXT bytes into per-layer provisional history slots ON CARD before returning;
this is not a current-history slot flip or whole-token state commit.
Dense arithmetic uses real on-card input, Q/K/V, attention and FFN. Both
retain existing source/metadata/NoC checks and the same worker-chain/hidden-
slot ADDRESSES. Runtime preservation of those chains is still unqualified.

The families compile separately so their layout aliases/private seals do
not collide. The recurrent Conv capsule calls its own renamed recurrent
seal. One checked device-zero helper also resolves compiler-emitted memset;
there is no host library/allocator or private CPU numerical oracle.
All existing production/diagnostic source files are UNMODIFIED.
