Decision / substantive change
------------------------------
Do not replace BF16-RNE with the hardware one-instruction rounding shortcut:
documented ties-away and zero normalization are not equivalent. Instead
prototype a DIFFERENT operation order:compute qdot=sum(q*x) for ORIGINAL
unsigned Q4 codes q0..15 using native BFP8_B,then correct each output with
  oldAccumulator + ((d*scale)*qdot + (-(dmin*minimum))*sum(x)).
This is NOT the old per-weight BF16-RNE or GGML accumulation order. No
rounding-equivalence/model-quality claim is made. It needs independent
numerical validation before any Work/Assistant selection.

Native BFP8_B exponent130 and positive magnitude q*8 represent every q
EXACTLY,including0 and15. TWO simple SFPU integer instructions extract
that code byte from either half of an original packed byte. This replaces
the old ten-operation nibble/cast/MAD/BF16-round SUBEXPRESSION ONLY.
It EXCLUDES raw loads,stores,PACK,L1 exponent assembly,UNPACK,four-fidelity
matrix work,metadata,input-sum production,output correction and lifetime.
Do NOT infer5x kernel/model speed,utilization or a new whole-model budget.

Intended integration keeps original compressed GDDR weights and creates
temporary native tiles ON CARD in L1. This is a design direction,NOT a
delivered packer/layout/residency guarantee. No expanded global BFP8 weight
model is created here. Real L1/source-bank/format/ownership proof is missing.
