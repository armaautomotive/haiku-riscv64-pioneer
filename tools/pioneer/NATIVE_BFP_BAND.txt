Full-K native BFP8/broadcast band prototype -- OFFBOARD ONLY
=========================================================

PioneerQ38NativeBfpBand.h and blackhole_q38_native_bfp_band.cpp execute ONE
32-output-row band across a COMPLETE input width5120,6144 or17408 after one
launch. This is not the complete output matrix,layer or model. Weights/inputs
must ALREADY be in the private L1 spans; no cache uploader,NoC/GDDR loader,
native owner,cohort or installed Work path selects this program. Driver/Work/
CPU-validation builds are deliberately rejected. Original shaders unchanged.

Two explicit compile-time variants
----------------------------------
phases4:all four BF16 fidelity terms (not IEEE-exact accumulator arithmetic).
phases1:phase0 ONLY,reduced-precision operand views. This is NOT a validation
toggle or a numerically equivalent optimization. No implicit2-phase selection
or fallback exists. Both shader variants perform learned products on FPU,
not scalar RISC or host. CPU reference calculations live only in tests.

The program sets up the private context once,clears Dst ONCE per complete
band and loops over160/192/544 cached native32x32 tiles. Each tile unpacks
weights and32 BF16 input values; MVMUL broadcasts SrcB rows0/1 instead of
loading8 redundant rows. All32 outputs accumulate in FP32 Dst rows32/40.
Only those valid broadcast rows are read; partially undefined replica rows
are never treated as output. Last face/phase releases BOTH source banks.
Real bounded completion precedes every descriptor rewrite and scalar result
read. This baseline still has per-tile completion/config overhead; eliminating
that safely with native counters/prefetch remains future performance work.
